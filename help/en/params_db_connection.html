DB connections — profile JSON files (WysiQ)

Access: ? button next to Catalog in the Data Sources window
(Main ▸ Database ▸ DB Connection).
This page describes the files that the Data Sources window reads and writes,
for anyone who wants to read or correct them directly with a text editor
(WysiQ closed or followed by ⟳ Reload). There is no longer a "DB connection"
tab in Parameters: all everyday input is done in Data Sources.
See also: help/en/datasource.txt (the Data Sources window)
          help/en/db_connections_json.txt (full file reference)
What you can edit here
data_sources.json
  One object per connection profile. Each profile carries the identity of its
  connector — family, provider, connector_service, connector_label,
  engine_type — and the non-sensitive parameters (host, port, database, schema,
  username, SSL mode, ...).
  Passwords are never to be typed into this file. Depending on the PWD box of
  the Data Sources window, a profile may contain password_enc (scrambled
  form); this value is produced by Data Sources, not by hand.
db_connection.json
  Optional. Defines the connector types and the form fields.
  Present only if your workspace overrides the bundled catalogue.
Optional SQL prefixes
  sql_before_select and sql_before_create, used by the DuckDB flows and by
  the creation scripts generated for the profile. They are described in
  db_connections_json.txt.
The five identity fields
Every saved profile keeps these keys explicitly. Do not remove them:
this is how WysiQ finds the right connector and the right engine on
reload.
  family              Local, Server, Cloud, API / NoSQL
  provider            Generic, Microsoft, Azure, AWS, Google Cloud, ...
  connector_service   internal connector identifier, e.g. aws_redshift
  connector_label     the displayed label, e.g. "Amazon Redshift"
  engine_type         the technical engine, e.g. postgresql
provider and engine_type answer two different questions: who operates the
service, and which engine it speaks. Several providers share the same
engine — this is normal and intended.
Manual editing
Edit the files with a text editor, then ⟳ Reload in Data
Sources. A malformed file is reported rather than silently ignored;
on the other hand, a syntactically valid file with a wrong engine_type
will simply fail at connection time. Only change this field if you know
why.
Keys starting with an underscore are documentation and are ignored
by WysiQ.
What is never saved
access_token, refresh_token, client_secret, private_key, secret_access_key and
service_account_private_key never reach any file, whatever you type
in the form. When a secrets manager or an external identifier
exists, WysiQ saves the reference, never the secret value.
Passwords follow the PWD box of Data Sources: unticked by
default (session only), or written under the password_enc key in
scrambled form. This scrambling prevents accidental reading; it is not
strong encryption. See help/en/datasource.txt.
