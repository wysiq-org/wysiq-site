AI CASE CENTER

Access: AI Command Center ▸ 🗂 AI Case Center, or Main ▸ AI ▸ AI Cases…
(a graph must be open).
Double-click an AI Case in the list: open it (make it active).
An AI Case is the complete, replayable record of an AI investigation built on a
WysiQuery: the questions you asked the AI (AI Prompts), the executions against
one or more AI Profiles, the answers and errors, the context that travelled
with each question (AI feeds — Area and data feeds), and the HTML reports
produced. Nothing is read from raw files here; every value comes from the
Case's own timeline through the CaseStore, which is an append-only log with
request / response correlation.

LAYOUT — TWO LISTS ON THE LEFT, DETAIL ON THE RIGHT

The window follows the same shape as the Metric catalog.
  AI Case (left column) — one row per Case, by name. The active Case is
  marked with a bullet.
  Query (right column) — the WysiQuery(ies) the selected AI Case is based on.
  Select a Case on the left to see which WysiQuery it rests on, the same way
  the Metric catalog shows "Series used" for a metric.
The right side is a pure inspector for the selected Case:
  AI Case header — Name, Created, Updated, Query (the WysiQuery name),
  Profiles, and Counts (prompts, executions, events, reports).
  AI Prompt tab — the questions asked to the AI. A broadcast that asked
  several Profiles the same question collapses to one prompt row, with the
  number of executions shown in the "x" column. Selecting a prompt lists its
  executions and responses (profile, tokens, provenance, errors).
  Summary / Prompts & executions / Grouped / Chat — full-Case views
  for deeper inspection. Double-click an event: opens the associated HTML
  report if there is one. Internal identifiers are not shown in the timeline;
  they remain available in the underlying Case files.

VOCABULARY

  Query = WysiQuery — the WysiQ query the Case is built on.
  AI Prompt = a question asked to the AI.
  Execution = one AI Prompt run against one AI Profile (one try).
  AI feed = the context sent with a question (Area or data feed), addressed by
  content fingerprint, never as raw data.

TOOLBAR

  Open folder — open the selected Case folder on disk.
  Add to AI Feed Stack — append feeds from the Sel-numbered AI Cases (or the
  highlighted Case if none are numbered) into the live AI Feed Stack, in Sel
  order, after the feeds already present. Click the Sel column on each Case to
  assign / clear its sequence. Trim or reorder in the AI Feed Stack window
  afterwards.
  ? — this help (right edge of the window).
  Close — close the window.

RIGHT-CLICK ON AN AI CASE

  Rename... — change the Case name.
  Duplicate... — clone the whole Case (timeline, feeds, reports, logs) into a
  new folder with a fresh identity. The original is never touched. A duplicate
  is the starting point for re-running the same Case on another WysiQuery or on
  updated data — for example, a different year.
  Delete... — permanently remove the Case folder and all its files. This
  cannot be undone.
The list refreshes on its own when you open, duplicate, delete or rename a
Case, so no manual refresh is needed.
ORIGINAL vs CURRENT DATA (in the AI Feed Stack)
A feed replayed from an AI Case can be sent either on the data that was
originally sent, or rebuilt on the current WysiQ data with the same recipe
(same bounds and shrink). This is chosen in the AI Feed Stack, per entry:
  Right-click the "Send #" column of an AI-Case feed → Original data / Current
  data. A tooltip shows the current mode.
  Right-click the "Feed" column → Delete, or Duplicate. Duplicate adds a second
  entry in the OPPOSITE data mode, so you can send both the original and the
  current version side by side (for example, comparing two years).
Feeds added from a window's AI button are always on current data and have no
such choice.
