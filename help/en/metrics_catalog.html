METRICS WINDOW — Help

Access: Main ▸ Metric ▸ Catalog; Series palette (right-click on the header
« Create Metric from "In" »); right-click on the X Axis combo (X metrics).
The Metrics window manages the catalogue of WysiQ metrics.
A metric is a virtual series, usually a combination of existing series with
coefficients, offsets, shifts and aggregations. It is stored in the
workspace under:
  workspace/metrics/<metric_name>.json
A metric is identified by its NAME only: the source table is kept as
metadata but is not part of its identity (several tables share the same
columns). The catalogue therefore never contains two metrics with the same
name.
This window is used to create, edit, find, import and check these metrics
without opening the JSON files directly.
Text zoom (help): Ctrl + mouse wheel or A− / A+ buttons
TWO TABS: METRICS AND SCENARIOS
The window is a notebook with two tabs.
Metrics tab
  The catalogue of metrics described below (filters, Metrics / Series used
  lists, detail, Metric Editor).
Scenarios tab
  Lists the scenarios saved in the workspace. Columns: Name, Created,
  Sample from (reference series), Points (number of control points), Source,
  Description. A "Points (X | Y)" preview shows the points of the selected
  scenario. Bar: Refresh, Search, Delete, JSON, → AI (drops the scenario
  JSON into the AI Feed Stack). A "Name like" filter narrows the list.

TOOLBAR

Refresh
  Reloads the catalogue from disk. Use it if files were added, deleted or
  modified outside the window.
Purge All
  Deletes all the duplicates detected in the metric catalogue (keeps one
  copy of each). A confirmation shows the number of files to delete before
  the action.
Search
  Searches for metrics in existing query JSON files. WysiQ opens a folder
  picker, then scans the .json files recursively and extracts the combined
  series found.
Create Metric
  Opens an empty Metric Editor to create a new metric. The series already
  known by the catalogue are offered as possible components.
JSON
  Shows / edits the JSON of the selected metric.
→ AI
  Drops the definition of the selected metric into the AI Feed Stack.
?
  Opens this help in the standard WysiQ help window.

LEFT PANEL: FILTERS AND LISTS

Catalog filters
  Metric like
    Filters the list of metrics on part of the name.
  Series like
    Filters the metrics that use at least one series whose name contains
    the text entered.
  Both filters can be used together.
Metrics list
  Shows the metrics matching the active filters.
  Single click   → selects and shows the detail on the right.
  Double-click   → opens the metric in the Metric Editor.
  Right-click    → context menu: → AI | Rename… | Duplicate… |
                   Purge duplicates (keep this one) | Delete.
  Sort:
    Left-click on the "Metrics" header   → alphabetical sort (A-Z / Z-A).
    Right-click on the "Metrics" header  → sort by date (newest/oldest).
  Purge rule:
    Duplicates are evaluated on the metric NAME only (the table is
    ignored): Purge All keeps the most recent entry of each name;
    "Purge duplicates (keep this one)" keeps the selected row.
  Rename…
    Changes the name of the metric. The JSON file is renamed; if a metric
    with that name already exists, WysiQ asks whether to overwrite it.
Series used list
  Shows the available series and those already used by metrics.
  Columns:
    Serie  column name or series name.
    In     presence dot if the series is used in at least one metric.
  The series come from the JSON definitions of the local and remote
  tables, as well as from the metrics already in the catalogue.
  Clicking a series automatically fills the Series like filter so that you
  see the metrics that use it.

RIGHT PANEL: METRIC INFORMATION

Metric block
  Metric   name of the selected metric.
  Created  creation date read from the JSON, or the file modification date
           if there is no creation date.
  Table    source table (metadata).
Find Queries
  Expands an area that searches for the queries using the selected
  metric.
  include history
    Also includes the query archives and the history subfolders.
  Queries
    List of the queries that reference the metric.
  Tables
    Tables associated with the queries found.
  → Use Find Queries before renaming or deleting a metric to check the
    impact.
Metric detail
  Shows a structured reading of the metric content: name, table, date,
  number of components, list of the series used and detail of each
  component.
  Also includes:
  - a Group by X line (ON/OFF, mode, window size, aggregate, lag/step when
    present)
  - a Where indicator per component (● if a series WHERE is active).
JSON
  Shows the raw JSON of the selected metric. Diagnostic area; changes must
  be made through the Metric Editor.

METRIC EDITOR

Window for creating and editing metrics.
Opened by Create Metric or by double-clicking an existing metric.
Each component can carry:
  - a source series;
  - a coefficient;
  - an offset;
  - a shift;
  - an aggregation;
  - a WHERE filter per component (operators + conditions);
  - an active/inactive status depending on the available options.
Behaviour of the WHEREs in the Metric Editor:
  - The per-component WHERE is set on each component row.
  - "Serie Where" is the global ON/OFF switch of all the component WHEREs.
  - "Metric Scope on X" adds WHERE conditions on the X axis for the
    computation.
  - The final global filtering of the metric is done in the WHERE of the
    Table palette.
Apply
  Saves the metric. A Save dialog confirms the name.
Save dialog
  Metric name
    Final name of the metric (Enter = Save).
  Source table kept as metadata
    Reminder of the source table (information only).
  Hint
    Tells whether the action will overwrite the existing file or create a
    new one.
  Save    Confirms writing the JSON.
  Cancel  Cancels the save.
If the name changes, WysiQ creates a new <name>.json file. If the name stays
the same and overwriting is confirmed, the existing file is replaced.

SEARCH: IMPORT METRICS FROM QUERIES

The Search button is used to retrieve metrics already present in existing
queries.
Process:
  1. Click Search.
  2. Choose a folder, typically workspace/queries.
  3. WysiQ goes through all the .json files of the folder and its
     subfolders.
  4. The combined series found are converted into metric files.
  5. The catalogue is refreshed.
WysiQ looks in particular for:
  - y_cfg blocks with expr_type="combo";
  - blocks containing combo_items;
  - series keys containing combo_items;
  - combo_items present at the root of a JSON.
The files created are written in workspace/metrics.
Existing duplicates are ignored to avoid overwriting a metric without
confirmation.

ACCESS FROM THE MAIN WINDOW

Metric menu → Catalog           opens this window.
Metric menu → Import…           imports metrics from a ZIP or .json
                                 (duplicates are ignored).
Metric menu → Export…           exports all the metrics of the workspace
                                 into a timestamped ZIP.
TIPS
- Use short but explicit metric names.
- Keep series names consistent across tables to reuse a metric.
- Use Find Queries before renaming or deleting a metric.
- Use Refresh after an external change to the metrics folder.
- Avoid editing the JSON by hand, except for occasional diagnosis.
- The JSON file name follows the pattern: <name>.json
  → changing the name in the Save dialog therefore creates a new file.
RECENT METRIC X0 OPTIONS
The Metric Editor now saves the X0 position settings with each metric.
Default
  Keeps the normal position of the metric on the graph.
Table X0
  Aligns the first non-null point of the metric with the X0 of its source
  table/query. In a multi-table query, sequential tables keep their offset;
  overlaid tables share the global X0.
Free X0
  Places the first non-null point of the metric at the X position entered.
  This is useful to compare quarters, campaigns, scenarios or time slices.
Metric Scope on X still defines the selected time range. X0 only
repositions the result of that range. A scenario can be shifted by using its
series in a metric and then applying the metric's X0 settings.

METRIC COPIED INTO A MULTI-TABLE QUERY

From a query, Apply in the editor copies the metric into the query and saves
it in the catalogue (the tooltips remind you). In multi-table, it goes into
the active tab: its simple columns ("Nucleaire") become those of that tab
("RTE2023_2.Nucleaire").
