AI MODEL CATALOG (Parameters ▸ AI ▸ Profile ▸ Catalog… / Discover…)

Browse known AI models and create Profiles from them. Opens in two modes:
Catalog (offline list) and Discover (live query of your providers).

MODELS — SORTED ALPHABETICALLY BY PROVIDER THEN BY NAME

Models are listed in alphabetical order — no favoritism. All providers
(anthropic, cursor, deepseek, google, groq, mistral, ollama, openai,
openrouter, qwen, xai…) appear in the same sorted list.
Within each provider group, models are also sorted alphabetically.

ICONS IN THE MODEL COLUMN

💾  Local — model runs on your PC or LAN (Ollama, LM Studio, Scan LLM…).
    WysiQ sends the full conversation history on every prompt; the model
    stays loaded in GPU/RAM between calls (Ollama warm start).
🔗  Server memory — the cloud provider keeps prompt cache or uploaded files
    between API calls (OpenAI, Anthropic, Gemini, Moonshot Kimi…). WysiQ
    can send large context once and reuse it — lower latency and cost on
    long sessions. Toggle "Use server memory when available" in the profile.
Models with neither icon are cloud APIs without file/cache memory
(OpenRouter, Mistral, Groq, DeepSeek, Qwen, XAI…) — full history inline
each time, but they work fine.
  🔗 OpenAI (gpt-5.x and later)
      Prompt cache + Files API (upload once, reference by file_id).
  🔗 Anthropic (Claude)
      cache_control ephemeral blocks + Files API (beta).
  🔗 Google (Gemini)
      Files API (48 h) + implicit cache above 32 K context.
  💾 Ollama / LM Studio
      No cloud memory API — history resent each prompt; no API key.
CATALOG vs DISCOVER
Catalog   Offline list bundled with WysiQ, always available.
Discover  Live query of providers you have an API key for. Shows only
          models reachable right now. Falls back to the offline catalog
          if a provider is unreachable.
Scan LLM…  (Parameters ▸ AI ▸ Profile) Live detection of Ollama, LM Studio
          and other OpenAI-compatible servers on this PC or LAN. Creates
          one profile per found model — ideal for qwen3-coder:30b on
          192.168.x.x without typing URLs. Help: ? in that dialog.
CATALOG ENTRY vs PROFILE
Catalog entry  A model description — provider, name, context size, tags.
               Read-only, the same for every WysiQ user.
Profile        Your own configured instance: model + API key + parameters
               (temperature, max tokens, timeout…). Checking models and
               clicking "Apply selection" creates one Profile per checked
               model, pre-filled with sensible defaults.
A single catalog model can produce several profiles (different keys,
temperatures, or named variants).

COLUMNS

☑ / ☐    Click anywhere on a row to toggle. Space bar also works.
Provider  The API provider (anthropic, openai, google…).
Model     Model name. ★ = WysiQ recommended. 💾 = local. 🔗 = server memory.
Ctx       Context window size in K tokens.
Tags      Capabilities: chat, reasoning, data, code, memory…
Status    exists = a profile already exists in this workspace.
          live   = model confirmed reachable (Discover mode only).

★ RECOMMENDED MODELS

A star marks models WysiQ recommends for analytical work. Use
"★ Rec" in the toolbar to reset checkboxes to just the starred models.

TOOLBAR BUTTONS

Filter: [___]  Type to narrow by provider, name, or tag.
All            Check every visible model.
None           Uncheck all.
★ Rec          Check only recommended models.
Apply selection  Create one Profile per checked model (skips existing ones)
                 and remove profiles for unchecked catalog-managed models.
Close          Close without changes.
?              This help.
Status column: state of the model (existing profile, available…).
Click the ☐ / ☑ box of a row: tick / untick it.
