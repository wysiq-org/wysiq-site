Data Sources — connection profiles (WysiQ)

Access: Main ▸ Database ▸ DB Connection (requires an open workspace).
Typical workflow:
  + New → Family / Provider / Type → fill in the fields → Test → Save
  → Connect → Catalog (choose the tables) → the tables appear in Main.
This window keeps the connection profiles WysiQ uses to reach your data:
local files, server databases, managed cloud databases, cloud warehouses,
object storage, APIs and NoSQL databases. A profile is then reused by the
SQL Assistant, the Table Catalog and imports/exports.
Non-sensitive parameters are saved in data_sources.json, in your workspace.
Passwords and tokens stay in session memory by default — see "Saving
passwords" below.
See also: help/en/db_connections_json.txt (files, SQL templates, dialects)
          help/en/params_db_connection.txt (profile JSON files)
Choosing a connector: Family, Provider, Type
The connector list is filtered by two drop-down lists (Family:, Provider:),
then a list:
Family       The kind of source: Local, Server, Cloud, API / NoSQL.
Provider     Who operates it: Generic, Microsoft, Azure, AWS, Google Cloud,
             Oracle Cloud, Snowflake, Databricks, MongoDB, etc.
Type         The actual service, for example "Azure SQL Database",
             "Amazon Redshift", "Google BigQuery", "IBM Db2".
Choose the family, then the provider, then the type in the list. The value
"All" in either list widens the choice. Examples:
  Family Cloud   > Provider AWS     > Type Amazon Redshift
  Family Cloud   > Provider Azure   > Type Azure SQL Database
  Family Server  > Provider Generic > Type IBM Db2
  Family Local   > Provider WysiQ   > Type DuckDB
The form fields change with the type. Only the fields useful to the
connector are shown; the examples show the expected format.
Cloning a connector
Right-click a connector of the Type list ▸ "Clone this connector…" to clone
it.
WysiQ asks for a key (the folder name) and a label, then copies the
connector into your workspace under connection_type/<key>/.
The copy declares the same engine as the original: it works immediately —
same driver, same SQL dialect, same catalog queries. No code is needed.
Use it when a service needs a variant specific to your site: an imposed
ODBC driver name, an extra field, a different default port, or an adjusted
list_tables.sql. Edit db-connection.json or the SQL files in the new
folder; the original connector is never modified, and your copy survives
WysiQ updates.
The key must start with a letter and contain only letters, digits and
underscores. A name already in use is refused.
Provider and engine are two different things
Many cloud services reuse a standard engine. Amazon RDS PostgreSQL, Azure
Database for PostgreSQL and Google Cloud SQL PostgreSQL are three distinct
services, but all three speak PostgreSQL. WysiQ stores both pieces of
information:
  provider      the environment (AWS, Azure, Google Cloud, ...)
  engine_type   the technical engine (postgresql, mysql, sqlserver, oracle, ...)
That is why a new managed service can be offered without a new driver: it
simply declares an existing engine. It also guarantees that the same engine
behaves the same way everywhere — same SQL dialect, same catalog queries.
"Sources" list (left panel)
Each row is a named profile, for example "Prod Oracle" or "Analytics
Snowflake". Columns:
  C        ● = profile connected for the session.
  Source   family icon + profile name.
  DB       profile number (the same as the DB column of the Main window).
  ⟳ Reload  Reloads the catalog of connector types from disk (useful after
            cloning or changing a connector).
  + New     Creates a profile with the default connector. Rename it in the
            Name field; the name must be unique.
  Delete    Deletes the selected profile after confirmation. The session
            secrets of that profile are cleared at the same time.
Right-click (or Ctrl+click) a profile:
  Duplicate…  copies the profile under a new name ("name (2)" proposed);
  Rename…     renames the profile;
  Delete…     deletes the profile after confirmation.
Buttons
Test      Opens a short connection and runs a harmless probe (typically
          SELECT 1, a version query, or a ping). Nothing is written to your
          database. A trace window shows each step: driver import,
          connection, version, number of tables, closing. Copy copies the
          trace; Close closes it.
Save      Writes the profile to data_sources.json, in the workspace.
          Passwords follow the PWD box described below.
Connect   Marks the profile active for this session so that the other
          windows can use it. No JSON file is rewritten. The button then
          shows Disconnect.
Catalog   Opens the Table Catalog for this profile: schemas, tables, views
          and columns read from the server. Available only for connectors
          that really support the catalog.
?         (next to Catalog) Opens the "params_db_connection" help on the
          connection JSON files.
?         (top right) Opens this help.
Saving passwords
By default, passwords and tokens live in memory for the current session and
are never written to disk. After restarting WysiQ, you type them again.
The PWD box next to Save changes this behaviour:
  unticked   "Passwords are session-only — never saved to disk."
             Nothing sensitive reaches data_sources.json.
  ticked     The password is written to the profile under the password_enc
             key, in scrambled form (never in clear text).
Read carefully: this scrambling prevents accidental reading of the JSON
file — a colleague opening it, a screenshot, a forgotten backup. It is not
strong encryption. Anyone holding the file and the application can recover
the password. Use the box for convenience on a personal machine; leave it
unticked for production credentials, or on any machine or folder you do
not control.
Whatever the setting, these values are never written to disk:
access_token, refresh_token, client_secret, private_key, secret_access_key,
service_account_private_key.
When a driver is missing
WysiQ loads no database driver at startup: a missing optional package
therefore cannot prevent the application from starting. The driver is
imported on the first connection. If it is missing, the Test states exactly
what to install, for the Python interpreter running WysiQ, for example:
  The postgresql connector requires the 'psycopg2-binary' package.
  Install it with: pip install psycopg2-binary
Some connectors are listed so that the profile can be prepared while their
engine is not yet wired in this version. The Test says so clearly rather
than faking a success.
Workspace files
data_sources.json
  One object per profile: the connector identity (family, provider,
  connector_service, connector_label, engine_type) and the non-sensitive
  parameters.
connection_type/<connector>/
  One folder per connector, copied from the application when the workspace
  is created. It contains the field definition and, for SQL connectors,
  editable SQL templates such as list_tables.sql. Your copy takes
  precedence over the shipped version, so a DBA can adjust a query after
  review.
connexions_cache/
  Caches of the object lists (tables, entity sets, collections) produced
  when you generate a catalog. Read-only discovery; nothing is run on the
  server.
Default security settings
WysiQ is read-oriented. Cloud connectors enable TLS/SSL by default and keep
certificate validation; no insecure mode is chosen for you. The Test never
runs a destructive statement.
Tips
  • Check the firewall, VPN and DNS before suspecting the connector.
  • On Windows, "localhost" resolves to IPv6 first; WysiQ forces
    127.0.0.1 for PostgreSQL because pg_hba.conf usually allows only the
    IPv4 address.
  • For ODBC connectors (Ingres, Db2, Sybase ASE, ...), the driver name must
    match exactly the entry in the Windows ODBC Data Source Administrator.
  • For Oracle Cloud with mTLS, fill in the wallet directory.
  • The Oracle service and connector_service are two distinct fields: the
    first is the Oracle service name, the second the internal identifier of
    the WysiQ connector.
