METRIC SCOPE — Help

Access: Metric editor ▸ ? button of the Where Series / NaN Policy bar.
Metric Scope defines the filters and restrictions applied when computing a
metric. The parameters are independent and cumulative.
☑ Where Series  (scope bar in the Metric Editor)
When checked (ON by default), WHERE clauses defined on the source series are
propagated to the metric computation.
Numeric example: if a source series is filtered with "<= 0" or
"< -15000", the metric is computed only on the points kept by that filter.
Excluded points become intentional NaN values.
Uncheck to get the raw value of every row, without the component filters.
NaN Policy  (next to Where Series)
This option defines how NaN values produced by the filters are handled in
composition calculations.
  NaN+x=x
    Flexible mode: NaN values are ignored when other values exist.
    Useful for ordinary sums of partially empty series.
  NaN+x=NaN
    Strict mode: if a condition series filters out a point, the result stays
    absent. Useful for event searches with several conditions,
    for example:
      PROD-CONSO < -15000
      AND Solar <= 0
    In that case, a zero-coefficient series can be used as a condition
    without creating a false horizontal line at 0.
Metric Scope on X  (button at the bottom of the Metric Editor)
Standard WHERE popup with c1 / c2 / c3 operators applied to the X axis.
Examples:
  c1 :  >=  2020-01-01
  join: AND
  c2 :  <=  2023-12-31
  → The metric is computed only over the 2020–2023 range.
  c1 :  >=  0
  join: AND
  c2 :  <=  120000
  → Numeric restriction on X.
📅 button on each value field: opens the date picker
(Day / Month / Year) and inserts the date in ISO format YYYY-MM-DD.
The filter is enabled automatically as soon as a value is typed (Where ON
box). + button: shows / hides condition c3. Apply confirms,
Cancel closes without changes. The label next to the button shows the active
filter or "not set".
X0 placement  (positioning mode, after computation)
Controls where the first non-zero point of the metric is placed on the X
axis once the computation is done. Three modes:
  none      Default behaviour: no repositioning.
  Table X0  Follows the X0 of the table / query in multi-table
            layouts.
  Free X0   Places the first non-zero scoped point at the requested graph
            row index. The length is already defined by Metric Scope on X.
This placement acts after the computation; it does not filter data.
Table row filtering
The "Metric Where" filter of older versions has been removed. Table rows are
now filtered through a single path: the WHERE of the Table palette. To
restrict rows BEFORE aggregation, define the WHERE on the series / table
concerned; Where Series then propagates it to the metric computation.
Combination and summary
Where Series + NaN Policy + Metric Scope on X + X0 placement can be active
at the same time. The summary "Scope: X + S + X0" shows which filters are
active:
  X   = Metric Scope on X (X axis)
  S   = Where Series (propagated source-series filters)
  X0  = Table X0 or Free X0 placement
The summary shows "Scope: none" when none is active.
