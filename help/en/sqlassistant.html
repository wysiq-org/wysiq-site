SQL Assistant — Help

Access: Main ▸ Database ▸ Table / View.
The SQL Assistant creates DuckDB work tables without writing SQL.
It lets you select, rename, filter, format, join or stack columns, then
materialise the result as a TABLE (views are no longer created: a table
can contain computed metrics).
Typical workflow:
  Connection → Mode → choose the table(s) → tick the columns, WHERE,
  formats, computed series → EXEC (preview) → CREATE (Export Table window)
  → the table appears in Main; Create (recipe) to redo it later.
HEADER
  Mode:          Single table or GRID JOIN / UNION.
  Connection:    Local (DuckDB) or a connected profile; the ● dot shows the
                 connection state. ↺ rereads the table list.
  ?              This help.
  Shrink to:     Auto N / Every N (row reduction, see SHRINK).
  Rows max       Number of preview rows (Enter to apply).
  ◄ 100 / 100 ►  Previous / next page of the preview.
MODES
Single table
  Work on a single table: column selection, WHERE filters, renaming,
  date formats and computed series.
  Sort…          sort on several columns (ASC box per level; Apply,
                 Clear, Cancel).
  GLOBAL WHERE   enables / disables all the column WHERE clauses.
  Add row nb     adds a row-number column.
  Column list:   double-click = properties; right-click = WHERE…,
                 Compose metric… (new computed series from the column),
                 Edit metric… (existing computed series).
  Value list:    double-click to edit (Enter confirms, Escape cancels);
                 ◀ 100 / 100 ▶ scroll the rows.
GRID JOIN / UNION
  Multi-table work. Add tables with Add → (← Remove removes them), choose
  JOIN or UNION, tick Sel for the output columns, Join for the join keys,
  then choose LEFT or FULL and the Base table.
  LEFT  keeps all rows of the Base table and adds the matching values of
        the other tables. Each additional table joins directly on the
        Base key, without cascading COALESCE.
  FULL  keeps all rows of all tables. Join keys are merged with COALESCE
        over all tables.
  The generated SQL uses one CTE per table (named TABLE_j) that renames
  the columns with a table prefix (RTE13_Consommation, …), then a clean
  SELECT with explicit LEFT JOINs. Click Edit SQL to inspect or copy the
  generated query.

FORMATS AND RENAMING

Double-click a column row or right-click to open the column properties.
There you can change the output name and the date format (list of presets
or typed entry) in the same dialog; Apply confirms, Clear all clears the
column settings, Cancel closes.
To compare several years on the same calendar axis, map the real dates to
a common reference year:
  Format: %d/%m/2000 %H:%M
  Effect: 2013-07-15 08:30  →  2000-07-15 08:30
          2024-07-15 08:30  →  2000-07-15 08:30
Year 2000 keeps the result as a valid TIMESTAMP, usable as a datetime axis
in graphs. By applying this format to the join column in a GRID JOIN, you
overlay several years on the same X axis.
When a format is set on a column in one panel, it propagates automatically
to the same column in all the other panels.

TYPE HARMONISATION

In GRID JOIN mode, if a numeric column exists as BIGINT in the Base table
and as DOUBLE in another table (same numeric family), the generated SQL
adds a CAST to match the Base type. Columns of really different types
(e.g. INTEGER vs VARCHAR) are left as they are.

ADD SERIE

+ Add Serie opens the composition editor. It creates a column computed
from numeric columns: sum, difference, ratio, weighted combination,
coefficients, etc. The result is propagated to all panels in GRID mode.
SHRINK (UNION mode)
Each table panel has its own Shrink controls:
  Auto N   — keep approximately N rows (one row out of k)
  Every N  — keep exactly one row every N rows
This balances tables of very different sizes in a UNION.

RECIPES

Recipes save and restore the full configuration of the SQL Assistant. They
are stored as individual JSON files in the recipes/ folder of the
workspace. The generated SQL is NOT stored — it is always regenerated from
the current table definitions when a recipe is applied.
Buttons (2×2 grid):
  Create  saves the current configuration as a new recipe.
  Delete  deletes the selected recipe.
  Load    refreshes the recipe list from disk.
  Apply   restores the selected recipe and regenerates the SQL.
Double-click a recipe to apply it immediately.
Right-click a recipe for more options:
  → AI        send the recipe to the AI Feed Stack
  Apply       apply the recipe
  Rename…     rename the recipe file
  Duplicate…  create a copy under a new name
  Delete      delete the recipe
Hover over a recipe name to see a tooltip with its mode, its tables and
its last modification date.
Recipe JSON format (GRID mode, version 2):
  mode, operation, join_type, base_table, global_where
  tables[]  — per table: selected_cols, join_cols, formats,
              aliases, where, computed_cols, shrink
  restore_policy — ignore_missing_columns: true by default
  output    — suggested_name, default_kind
On Apply, the proposed output name is pre-filled with the recipe name.

GLOBAL WHERE

Tick GLOBAL WHERE to apply the column filters to all tables in GRID mode.
Each table keeps its own WHERE definition; the box enables or disables
them all.

PREVIEW AND CREATE

EXEC       runs the SQL and shows the data preview.
■          interrupts a running query.
CREATE     opens the Export Table window ("copy_table" help) to
           materialise the result as a WysiQ TABLE (DuckDB + Parquet), and
           optionally push it to a remote database.
Close      closes the SQL Assistant.
Edit SQL   opens the full SQL in an editable popup (Courier font).
           Export (copy) copies the query, Import (paste) pastes a query
           from the clipboard, Apply & Run runs it, Close closes.
Show Table switches from the GRID builder to the Single table view of the
           combined result (all columns selected by default).
← Grid     returns to the GRID builder and removes the temporary view.
