AI Observatory

Access: Parameters ▸ AI ▸ Observatory (the window opens when the tab is
selected; Observatory Settings… button); Main ▸ AI ▸ Observatory… opens the
observatory web page.
"AI Observatory" WINDOW — CONTROLS
  Enable activity tracking   enables / disables sending the counters.
  Preset:                    Local test, WysiQ cloud, Enterprise intranet,
                             Custom (pre-fills the URL).
  Activity URL:              address of the activity server.
  Mode:                      Anonymous counters (default: counters
                             only) or Enterprise opt-in (extra fields,
                             company server).
  Fields sent                Field / Send / Privacy list; double-click an
                             optional row to switch it ON / OFF.
  JSON preview               exact preview of what will be sent.
  Privacy rule               reminder: no data, no SQL, no prompt,
                             no table name; the theme is detected
                             locally.
  Open AI observatory / Open Share observatory   open the web pages.
  Test local server          starts a local test server (see below).
  Save / Close / ?           save, close, help.
This page configures the WysiQ AI Observatory: what WysiQ counts,
what it never sends, and how to feed either the public wysiq.org
observatory or a company-internal activity server.
Scope of this version
This version of the WysiQ Observatory tracks AI usage (provider, model,
tokens, language, OS, version, anonymous instance id) on the AI observatory
page, and is structurally ready to track network/social shares and exports
(platform, content type, export format) on the separate Share observatory
page — but no WysiQ feature calls the share/export counter yet, so the
Share observatory will show zero until that instrumentation is added to
the relevant share/export code paths in a future version.
Purpose
WysiQ can count real AI usage without transmitting the analysed data.
The goal is twofold:
1) www.wysiq.org / public WysiQ observatory
   - show the AIs most used by WysiQ analyses
   - count AI sessions, models, tokens and WysiQ versions
   - stay in anonymous-counters-only mode
2) Company / intranet server
   - track the company's internal AI consumption
   - consolidate tokens by model, provider, version or user
     if the company enables it
   - keep all data on a server chosen by the customer, without
     sending anything to wysiq.org
Public WysiQ mode
Public mode must stay minimal. Fields sent:
- WysiQ version
- WysiQ language
- operating system
- anonymous instance id
- AI provider
- AI model
- number of requests
- input / output / total tokens
Never sent in public mode:
- raw data
- table names
- SQL queries
- full prompts
- analysis results
- Windows user name
- computer name
- email or personal identity
- IP geolocation
Enterprise opt-in mode
Enterprise opt-in mode lets a company add extra fields, but only on
ITS OWN server (never on wysiq.org):
- User / login
- Query name
- Table name
- AI session id
- Workspace id
- Project / business unit
These fields are explicit options, to be enabled one by one in the
"Fields sent" list of the configuration window. They serve an IT
department or a data team that wants to track internal AI consumption
per user or per project.
WysiQ configuration files
The local configuration is stored in the workspace:
   <workspace>/activity/activity_config.json
This file contains in particular:
- enabled: enables/disables tracking
- server_url: URL of the target activity server
- instance_id: anonymous id created once per workstation
- tracking_mode: anonymous or enterprise
- fields: fields enabled in the list of the configuration window
- send_errors_to_log: keeps local sending errors
The local logs of the WysiQ workstation are:
   <workspace>/activity/activity_sent.jsonl
   <workspace>/activity/activity_errors.jsonl
activity_sent.jsonl lets you check exactly what WysiQ tried to send
(useful to verify that no sensitive data leaves).
activity_errors.jsonl helps diagnose an invalid server URL or a stopped
server.
Local test server (on this workstation)
The "Test local server" button starts, in a visible CMD window, the local
test server shipped with WysiQ:
   py -m xiquery.activity.local_activity_server
Local pages:
   http://127.0.0.1:8088/ai.html         AI observatory (AI usage counters)
   http://127.0.0.1:8088/share.html      Share observatory (share + export counters)
   http://127.0.0.1:8088/ping            server availability test
Event reception endpoint:
   http://127.0.0.1:8088/api/activity
Storage file of the local server:
   <workspace>/activity/server_data/activity_events.jsonl
This local server is only meant for tests on the development
workstation: it stops when its CMD window is closed and must not be
used for real production tracking.
Company / intranet server: detailed activation
WysiQ provides a turnkey standalone server for a company that wants to
feed its OWN WysiQ AI activity counters, without sending anything to
wysiq.org. It is a single Python file with no dependency on the rest of
WysiQ: it only needs standard Python 3 (no library to install), so it can
be copied and run on any workstation or server of the company network.
This file is already provided and copied automatically into every
workspace, with no action on your part, under:
   <workspace>/techroom/WYSIQ_ACTIVITY_SERVER.py
   <workspace>/techroom/WYSIQ_ACTIVITY_SERVER.bat
   <workspace>/techroom/WYSIQ_ACTIVITY_SERVER_README_FR_EN.txt
Steps to enable it and feed the company counters:
1) Get the files from the workspace:
      <workspace>/techroom/WYSIQ_ACTIVITY_SERVER.py
      <workspace>/techroom/WYSIQ_ACTIVITY_SERVER.bat
2) Copy them together onto the machine that will act as the activity
   server (an intranet server, or simply a workstation that is always on
   and reachable by the other WysiQ workstations for a first trial).
3) Start the server on that machine. On Windows, the simplest way is to
   double-click WYSIQ_ACTIVITY_SERVER.bat: it detects Python (py or
   python) automatically, shows a clear message if it is not installed,
   and keeps the window open to follow the activity logs. Otherwise, from
   the command line (Windows, Linux, macOS):
      py WYSIQ_ACTIVITY_SERVER.py
   or:
      python WYSIQ_ACTIVITY_SERVER.py
   Note: the .bat file is only copied automatically into new workspaces
   (or existing techroom folders that do not have it yet); a workspace
   created before this version will not receive it by itself, so copy it
   manually from <workspace>/techroom/ or from the program's
   assets/techroom/ folder.
   Optional environment variables, to set before starting if the default
   values do not suit:
      WYSIQ_ACTIVITY_HOST   default 0.0.0.0 (listens on all interfaces)
      WYSIQ_ACTIVITY_PORT   default 8088
      WYSIQ_ACTIVITY_DATA   default ./server_data (JSONL storage folder)
4) Check from a browser, on that machine or on another workstation of
   the network:
      http://SERVER_NAME:8088/ping
      http://SERVER_NAME:8088/ai.html         AI observatory (AI counters)
      http://SERVER_NAME:8088/share.html      Share observatory (share + export counters)
5) On EACH WysiQ workstation that must feed this company server, open:
      Settings ▸ Parameters… ▸ AI ▸ Observatory ▸ "Observatory Settings…"
6) Choose the preset:
      Enterprise intranet
7) Enter the activity URL with the name or IP of the company server:
      http://SERVER_NAME:8088/api/activity
From then on, every completed AI session on that WysiQ workstation sends
its counters (provider, model, tokens, language, OS, version) to this
company server. The /ai.html and /share.html pages refresh automatically
every 5 seconds: just leave them open to watch activity live.
Company-server storage:
   server_data/activity_events.jsonl
Each line is an independent JSON event. This format is easy to read back
with Python, Excel/PowerQuery, DuckDB, SQLite, PostgreSQL or a BI tool,
for deeper use than the two HTML pages provided.
The two queryable API endpoints (used by the HTML pages, but also directly
usable by a BI tool) return the same kind of JSON response:
   GET /api/stats/public   aggregated counters, without event details
   GET /api/stats/admin    same counters, plus the list of the last 50
                           raw events (recent_events)
Typical response:
   {
     "totals": {
       "active_instances": 12, "ai_sessions": 340,
       "total_tokens": 512000, "input_tokens": 410000,
       "output_tokens": 102000, "events_count": 480
     },
     "top_providers": [["anthropic", 300000], ["openai", 212000]],
     "top_models":    [["claude-sonnet-4-6", 280000], ["gpt-4o", 232000]],
     "languages":      [["fr", 300], ["en", 40]],
     "os":             [["Windows", 320], ["Linux", 20]],
     "versions":       [["1.2.4", 340]]
   }
The company server reuses exactly the same HTML files and the same counter
computation as the local test server: both implementations are kept
identical so that the same dashboard behaves the same way, whether the
data comes from a local test or from a real company server.
Privacy rule
The public WysiQ server knows that an AI analysis took place, but never
knows what it was about.
The User, Query, Table, Project and Workspace fields are reserved for
company servers and must remain an explicit choice of the customer,
never enabled by default, and never sent to www.wysiq.org.
Activity theme detection
WysiQ can add a compact activity theme to the AI usage counters, for
example energy, finance_accounting or manufacturing. The theme is computed
locally from a flat list of table and column names with:
  WysiQ/activity/domain_keywords.json       optional company dictionary
  activity/domain_keywords.json             bundled standard dictionary
                                            (program folder)
No data row, no SQL query, no prompt, no DDL, no key, no relation, no
index and no raw column list is sent to the WysiQ Observatory. Only the
computed theme, its label and its confidence level are sent with the
token counters.
When a query is saved, WysiQ also stores the detected theme in the query
JSON. When an AI Analyst window is opened from a query or a graph, the
theme is recomputed from the current context so that the AI Activity page
can show AI usage by practical business domain.
