Export Table — what happens when you click EXEC (technical reference)

Companion page of the "copy_table" help (? button of the Export Table
window). It describes the order of operations, for anyone who wants to
understand the files written in the workspace.
1) Before EXEC (preparation)
• Target table, Owner and Target connection are read from the window.
• For a remote connection, the profile dialect (data_sources.json,
  engine_type) is used to build the CREATE TABLE script shown by the SQL
  button. This script is informative: it is not executed by the SQL button.
• The SQL templates of connection_type/<connector>/ (list_tables.sql…) are
  used for catalog discovery; they are not executed by EXEC.
2) When EXEC is clicked (order of operations)
• Name check; if the table exists: "Overwrite it?" (Yes = replace).
• Full read of the source: file reread in full (Check file mask and
  shrink applied), table or SQL result.
• DROP TABLE IF EXISTS then CREATE TABLE in the workspace DuckDB session.
  WysiQ always creates a TABLE (views are no longer created here).
• Writing of the .parquet file and of the tables/<name>.json definition
  (table_mode, source, columns, owner), update of the registry
  tables/_registry.json and of the Main list.
• Remote connection chosen: rows written to the server according to
  Remote push (Create / recreate, Append, Delete all rows then insert).
3) After EXEC
• The table is available to Queries, the Table Catalog and the SQL
  Assistant.
• From the SQL Assistant, a recipe can be saved under recipes/ to
  recreate the table later; it is independent of EXEC.
See also: copy_table (Export Table window), db_connections_json (connection
files and dialects).
