QUERY — Last PCA / Axes

Role
This area documents the latest PCA computed from Area.
It does not replace Area: Area computes, Query documents.
Query as a PCA recipe
The query.json file keeps the process that produced the latest PCA:
- work table,
- source columns,
- Metrics defined in the Query,
- A-enabled series in the Series palette,
- X/Y bounds used,
- number of PCs,
- explained variance,
- coefficients and contributions.
The Query is therefore a PCA analytical recipe, not only a SQL query.
Stored
WysiQ stores only a compact summary of the latest PCA:
- number of rows used,
- number of input series,
- Area bounds used,
- computed PCs,
- explained percentage for each PC,
- cumulative percentage,
- main contributing series,
- coefficients and contributions.
Not stored
AXIS_* values are not written into query.json:
- AXIS_PC1, AXIS_PC2, ...
- AXIS_RECONSTRUCTION_ERROR
- AXIS_DIST_PCA
To use them in Metrics, Signals or Table, create them from Area with Create PCA.
To keep them permanently, export/materialize a work table.
Display
The variance table shows PC1, PC2, etc. and the cumulative information.
The loadings table displays the main contributing series for each PC to avoid flooding the user with every series.
P1%, P2%, ... show the relative contribution of the series in each PC.
Dom.PC shows the dominant PC for the series.
Σ|coef| gives a compact global-importance indicator.
WysiQ rule
Area computes.
Query stores the latest summary.
Post-it/PPTX keep multiple states.
A materialized table keeps PC values permanently.
