FENÊTRE METRICS — Aide

Accès : Main ▸ Metric ▸ Catalog ; palette Series (clic droit sur l'en-tête
« Create Metric from "In" ») ; clic droit sur le combo X Axis (métriques X).
La fenêtre Metrics gère le catalogue des métriques WysiQ.
Une métrique est une série virtuelle, généralement une combinaison de séries
existantes avec coefficients, offsets, décalages et agrégations. Elle est
stockée dans le workspace sous :
  workspace/metrics/<nom_metrique>.json
Une métrique est identifiée par son NOM seul : la table d'origine est gardée
comme métadonnée, mais n'entre pas dans l'identité (plusieurs tables partagent
les mêmes colonnes). Le catalogue ne contient donc pas deux métriques de même
nom.
Cette fenêtre sert à créer, modifier, retrouver, importer et contrôler ces
métriques sans ouvrir directement les fichiers JSON.
Zoom texte (aide) : Ctrl + molette ou boutons A− / A+
DEUX ONGLETS : METRICS ET SCENARIOS
La fenêtre est un notebook à deux onglets.
Onglet Metrics
  Le catalogue des métriques décrit ci-dessous (filtres, listes Metrics /
  Series used, détail, Metric Editor).
Onglet Scenarios
  Liste les scénarios enregistrés dans le workspace. Colonnes : Name,
  Created, Sample from (série de référence), Points (nombre de points de
  contrôle), Source, Description. Un aperçu « Points (X | Y) » montre les
  points du scénario sélectionné. Barre : Refresh, Search, Delete, JSON,
  → AI (dépose le JSON du scénario dans l'AI Feed Stack). Un filtre
  « Name like » restreint la liste.

BARRE D'OUTILS

Refresh
  Recharge le catalogue depuis le disque. À utiliser si des fichiers ont été
  ajoutés, supprimés ou modifiés hors de la fenêtre.
Purge All
  Supprime tous les doublons détectés dans le catalogue de métriques (garde
  une copie de chaque). Une confirmation indique le nombre de fichiers à
  supprimer avant l'action.
Search
  Recherche des métriques dans des fichiers query JSON existants. WysiQ ouvre
  un sélecteur de répertoire, puis scanne récursivement les fichiers .json et
  extrait les séries combinées trouvées.
Create Metric
  Ouvre le Metric Editor vide pour créer une nouvelle métrique. Les séries
  déjà connues par le catalogue sont proposées comme composants possibles.
JSON
  Affiche / édite le JSON de la métrique sélectionnée.
→ AI
  Dépose la définition de la métrique sélectionnée dans l'AI Feed Stack.
?
  Ouvre cette aide dans la fenêtre d'aide standard WysiQ.

PANNEAU GAUCHE : FILTRES ET LISTES

Catalog filters
  Metric like
    Filtre la liste des métriques sur une partie du nom.
  Series like
    Filtre les métriques qui utilisent au moins une série dont le nom
    contient le texte saisi.
  Les deux filtres peuvent être utilisés ensemble.
Liste Metrics
  Affiche les métriques correspondant aux filtres actifs.
  Clic simple    → sélectionne et affiche le détail à droite.
  Double-clic    → ouvre la métrique dans le Metric Editor.
  Clic droit     → menu contextuel : → AI | Rename… | Duplicate… |
                   Purge duplicates (keep this one) | Delete.
  Tri :
    Clic gauche sur l'en-tête "Metrics"  → tri alphabétique (A-Z / Z-A).
    Clic droit sur l'en-tête "Metrics"   → tri par date (plus récent/ancien).
  Règle de purge :
    Les doublons sont évalués sur le seul NOM de la métrique (la table est
    ignorée) : Purge All garde l'entrée la plus récente de chaque nom ;
    « Purge duplicates (keep this one) » garde la ligne sélectionnée.
  Rename…
    Change le nom de la métrique. Le fichier JSON est renommé ; si une
    métrique de ce nom existe déjà, WysiQ demande s'il faut l'écraser.
Liste Series used
  Affiche les séries disponibles et celles déjà utilisées par des métriques.
  Colonnes :
    Serie  nom de colonne ou nom de série.
    In     point de présence si la série est utilisée dans au moins une
           métrique.
  Les séries proviennent des définitions JSON des tables locales et
  distantes, ainsi que des métriques déjà présentes dans le catalogue.
  Cliquer sur une série remplit automatiquement le filtre Series like afin
  de voir les métriques qui l'utilisent.

PANNEAU DROIT : INFORMATIONS DE LA MÉTRIQUE

Bloc Metric
  Metric   nom de la métrique sélectionnée.
  Created  date de création lue dans le JSON, ou date de modification du
           fichier si la date de création n'existe pas.
  Table    table d'origine (métadonnée).
Find Queries
  Déplie une zone qui recherche les queries utilisant la métrique
  sélectionnée.
  include history
    Inclut aussi les archives de queries et les sous-répertoires history.
  Queries
    Liste des queries qui référencent la métrique.
  Tables
    Tables associées aux queries trouvées.
  → Utiliser Find Queries avant de renommer ou supprimer une métrique
    pour vérifier l'impact.
Metric detail
  Affiche une lecture structurée du contenu de la métrique : nom, table,
  date, nombre de composants, liste des séries utilisées et détail de
  chaque composant.
  Inclut aussi :
  - une ligne Group by X (ON/OFF, mode, taille de fenêtre, agrégat, lag/step si présents)
  - un indicateur Where par composant (● si un WHERE série est actif).
JSON
  Affiche le JSON brut de la métrique sélectionnée. Zone de diagnostic ;
  la modification doit se faire via le Metric Editor.

METRIC EDITOR

Fenêtre de création et d'édition des métriques.
Ouvert par Create Metric ou par double-clic sur une métrique existante.
Chaque composant peut porter :
  - une série source ;
  - un coefficient ;
  - un offset ;
  - un décalage ;
  - une agrégation ;
  - un filtre WHERE par composant (opérateurs + conditions) ;
  - un statut actif/inactif selon les options disponibles.
Comportement des WHERE dans le Metric Editor :
  - Le WHERE par composant se règle sur chaque ligne de composant.
  - « Serie Where » est l'interrupteur ON/OFF global de tous les WHERE composants.
  - « Metric Scope on X » ajoute des conditions WHERE sur l'axe X pour le calcul.
  - Le filtrage global final de la métrique se fait dans le WHERE de la palette Table.
Apply
  Enregistre la métrique. Un dialogue Save confirme le nom.
Save dialog
  Metric name
    Nom final de la métrique (Entrée = Save).
  Source table kept as metadata
    Rappel de la table d'origine (information seulement).
  Hint
    Indique si l'action va écraser le fichier existant ou en créer un
    nouveau.
  Save    Valide l'écriture du JSON.
  Cancel  Annule l'enregistrement.
Si le nom change, WysiQ crée un nouveau fichier <nom>.json. Si le nom reste
identique et que l'écrasement est confirmé, le fichier existant est remplacé.

SEARCH : IMPORTER DES MÉTRIQUES DEPUIS DES QUERIES

Le bouton Search sert à récupérer des métriques déjà présentes dans des
queries existantes.
Processus :
  1. Cliquer sur Search.
  2. Choisir un répertoire, typiquement workspace/queries.
  3. WysiQ parcourt tous les fichiers .json du répertoire et de ses
     sous-dossiers.
  4. Les séries combinées trouvées sont converties en fichiers de
     métriques.
  5. Le catalogue est rafraîchi.
WysiQ cherche notamment :
  - des blocs y_cfg avec expr_type="combo" ;
  - des blocs contenant combo_items ;
  - des clés series contenant combo_items ;
  - des combo_items présents à la racine d'un JSON.
Les fichiers créés sont écrits dans workspace/metrics.
Les doublons déjà existants sont ignorés pour éviter d'écraser une
métrique sans confirmation.

ACCÈS DEPUIS LA FENÊTRE PRINCIPALE

Menu Metric → Catalog           ouvre cette fenêtre.
Menu Metric → Import…           importe des métriques depuis un ZIP ou .json
                                 (les doublons sont ignorés).
Menu Metric → Export…           exporte toutes les métriques du workspace
                                 dans un ZIP horodaté.

CONSEILS D'UTILISATION

- Utiliser des noms de métriques courts mais explicites.
- Garder des noms de séries cohérents entre tables pour réutiliser une
  métrique.
- Utiliser Find Queries avant de renommer ou supprimer une métrique.
- Utiliser Refresh après une modification externe du répertoire metrics.
- Éviter de modifier les JSON à la main, sauf diagnostic ponctuel.
- Le nom du fichier JSON suit le motif : <nom>.json
  → changer le nom dans le Save dialog crée donc un nouveau fichier.
OPTIONS RÉCENTES METRIC X0
Le Metric Editor sauvegarde maintenant les réglages de position X0 avec chaque métrique.
Default
  Conserve la position normale de la métrique sur le graphe.
Table X0
  Aligne le premier point non nul de la métrique sur le X0 de sa table/query source.
  En query multi-table, les tables séquentielles gardent leur décalage ; les tables
  superposées partagent le X0 global.
Free X0
  Place le premier point non nul de la métrique à la position X saisie.
  C'est utile pour comparer des trimestres, campagnes, scénarios ou tranches de temps.
Metric Scope on X définit toujours la plage de temps sélectionnée. X0 ne fait que
repositionner le résultat de cette plage. Un scénario peut être décalé en utilisant
sa série dans une métrique puis en appliquant les réglages X0 de la métrique.

MÉTRIQUE COPIÉE DANS UNE QUERY MULTI-TABLES

Depuis une query, Apply de l'éditeur copie la métrique dans la query et
l'enregistre dans le catalogue (les tooltips le rappellent). En
multi-tables, elle va dans l'onglet actif : ses colonnes simples
(« Nucleaire ») deviennent celles de cet onglet (« RTE2023_2.Nucleaire »).
