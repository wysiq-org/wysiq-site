Assistant SQL — Aide

Accès : Main ▸ Database ▸ Table / View.
L'Assistant SQL crée des tables de travail DuckDB sans écrire de SQL.
Il permet de sélectionner, renommer, filtrer, formater, joindre ou
empiler des colonnes, puis de matérialiser le résultat en TABLE (les vues
ne sont plus créées : une table peut contenir des métriques calculées).
Processus type :
  Connection → Mode → choisir la ou les tables → cocher les colonnes, WHERE,
  formats, séries calculées → EXEC (aperçu) → CREATE (fenêtre Export Table)
  → la table apparaît dans Main ; Create (recipe) pour la refaire plus tard.
EN-TÊTE
  Mode :         Single table ou GRID JOIN / UNION.
  Connection:    Local (DuckDB) ou un profil connecté ; le point ● indique
                 l'état de la connexion. ↺ relit la liste des tables.
  ?              Cette aide.
  Shrink to:     Auto N / Every N (réduction des lignes, voir SHRINK).
  Rows max       Nombre de lignes de l'aperçu (Entrée pour appliquer).
  ◄ 100 / 100 ►  Page précédente / suivante de l'aperçu.
MODES
Single table
  Travail sur une seule table : sélection de colonnes, filtres WHERE,
  renommage, formats de dates et séries calculées.
  Sort…          tri sur plusieurs colonnes (case ASC par niveau ; Apply,
                 Clear, Cancel).
  GLOBAL WHERE   active / désactive l'ensemble des WHERE de colonnes.
  Add row nb     ajoute une colonne de numéro de ligne.
  Liste des colonnes : double-clic = propriétés ; clic droit = WHERE…,
                 Compose metric… (nouvelle série calculée à partir de la
                 colonne), Edit metric… (série calculée existante).
  Liste des valeurs : double-clic pour éditer (Entrée valide, Échap
                 annule) ; ◀ 100 / 100 ▶ font défiler les lignes.
GRID JOIN / UNION
  Travail multi-tables. Ajoutez des tables avec Add → (← Remove les
  retire), choisissez JOIN ou UNION, cochez Sel pour
  les colonnes à sortir, Join pour les clés de jointure, puis choisissez
  LEFT ou FULL et la table Base.
  LEFT  conserve toutes les lignes de la table Base et ajoute les
        valeurs correspondantes des autres tables. Chaque table
        supplémentaire se joint directement à la clé de Base, sans
        COALESCE en cascade.
  FULL  conserve toutes les lignes de toutes les tables. Les clés de
        jointure sont fusionnées avec COALESCE sur toutes les tables.
  Le SQL généré utilise un CTE par table (nommé TABLE_j) qui renomme
  les colonnes avec un préfixe table (RTE13_Consommation, …), puis
  un SELECT propre avec des LEFT JOIN explicites. Cliquez sur Edit SQL
  pour inspecter ou copier la requête générée.

FORMATS ET RENOMMAGE

Double-cliquez sur une ligne de colonne ou clic-droit pour ouvrir les
propriétés de colonne. Vous pouvez y changer le nom de sortie et le
format de date (liste de préréglages ou saisie) dans le même dialogue ;
Apply valide, Clear all efface les réglages de la colonne, Cancel ferme.
Pour comparer plusieurs années sur un même axe calendaire, mappez les
dates réelles vers une année de référence commune :
  Format : %d/%m/2000 %H:%M
  Effet :  2013-07-15 08:30  →  2000-07-15 08:30
           2024-07-15 08:30  →  2000-07-15 08:30
L'année 2000 maintient le résultat en TIMESTAMP valide, utilisable
comme axe datetime dans les graphes. En appliquant ce format à la
colonne de jointure dans un GRID JOIN, vous superposez plusieurs
années sur le même axe X.
Quand un format est défini sur une colonne dans un panel, il se propage
automatiquement à la même colonne dans tous les autres panels.

HARMONISATION DES TYPES

En mode GRID JOIN, si une colonne numérique existe en BIGINT dans la
table Base et en DOUBLE dans une autre table (même famille numérique),
le SQL généré ajoute un CAST pour correspondre au type du Base. Les
colonnes de types vraiment différents (ex. INTEGER vs VARCHAR) sont
laissées telles quelles.

ADD SERIE

+ Add Serie ouvre l'éditeur de composition. Il crée une colonne
calculée à partir de colonnes numériques : somme, différence, ratio,
combinaison pondérée, coefficients, etc. Le résultat est propagé à
tous les panels en mode GRID.
SHRINK (mode UNION)
Chaque panel de table dispose de ses propres contrôles Shrink :
  Auto N   — conserver approximativement N lignes (une ligne sur k)
  Every N  — conserver exactement une ligne toutes les N lignes
Cela permet d'équilibrer des tables de volumes très différents en UNION.

RECIPES

Les recipes sauvegardent et restaurent la configuration complète de
l'Assistant SQL. Elles sont stockées comme fichiers JSON individuels
dans le dossier recipes/ du workspace. Le SQL généré n'est PAS
stocké — il est toujours régénéré depuis les définitions de tables
courantes lors de l'application d'une recipe.
Boutons (grille 2×2) :
  Create  enregistre la configuration actuelle comme nouvelle recipe.
  Delete  supprime la recipe sélectionnée.
  Load    rafraîchit la liste des recipes depuis le disque.
  Apply   restaure la recipe sélectionnée et régénère le SQL.
Double-cliquez sur une recipe pour l'appliquer immédiatement.
Clic-droit sur une recipe pour plus d'options :
  → AI        envoyer la recipe dans l'AI Feed Stack
  Apply       appliquer la recipe
  Rename…     renommer le fichier recipe
  Duplicate…  créer une copie sous un nouveau nom
  Delete      supprimer la recipe
Survolez un nom de recipe pour voir un tooltip avec son mode, ses
tables et sa date de dernière modification.
Format JSON de recipe (mode GRID, version 2) :
  mode, operation, join_type, base_table, global_where
  tables[]  — par table : selected_cols, join_cols, formats,
              aliases, where, computed_cols, shrink
  restore_policy — ignore_missing_columns: true par défaut
  output    — suggested_name, default_kind
A l'Apply, le nom de sortie proposé est pré-rempli avec le nom de la recipe.

GLOBAL WHERE

Cochez GLOBAL WHERE pour appliquer les filtres de colonnes à toutes les
tables en mode GRID. Chaque table garde sa propre définition WHERE ;
la case active ou désactive l'ensemble.

PREVIEW ET CREATE

EXEC       exécute le SQL et affiche l'aperçu des données.
■          interrompt une requête en cours.
CREATE     ouvre la fenêtre Export Table (aide « copy_table ») pour
           matérialiser le résultat en TABLE WysiQ (DuckDB + Parquet), et
           éventuellement le pousser vers une base distante.
Close      ferme l'Assistant SQL.
Edit SQL   ouvre le SQL complet dans une popup éditable (police Courier).
           Export (copy) copie la requête, Import (paste) colle une requête
           du presse-papiers, Apply & Run l'exécute, Close ferme.
Show Table passe du constructeur GRID à la vue Single table du résultat
           combiné (toutes les colonnes sélectionnées par défaut).
← Grid     retourne au constructeur GRID et supprime la vue temporaire.
