AI SESSION CENTER — WysiQ

Note (version actuelle) : la fenêtre AI Session historique n'est plus ouverte
par aucun menu — les sessions ont été remplacées par les AI Cases (AI Command
Center ▸ 🗂 AI Case Center, Main ▸ AI ▸ AI Cases…). Cette page reste la
référence pour les sessions créées avec les versions précédentes.

OBJECTIF

AI Session Center est l'outil d'archivage et de rejeu des conversations
de AI Analyst. Il ne dialogue pas directement avec l'IA : c'est AI
Analyst qui envoie les questions et reçoit les réponses, et chaque
échange est archivé automatiquement ici.
AI Session Center permet de :
  - parcourir les sessions et leur historique complet d'événements
  - consulter l'instantané du Query Core et toute réponse IA archivée
  - constituer une file de rejeu à partir de questions passées
  - rejouer des étapes sélectionnées sur la query/table courante dans
    AI Analyst
Philosophie : DATA → QUERY → AI SESSION → KNOWLEDGE

SESSION UNIQUE PARTAGÉE PAR TOUS LES PROFILS

Une session WysiQ est unique et partagée entre tous les profils IA qui
y participent. Il n'y a pas une session par profil.
  Structure de la session
    La session contient un historique séquentiel de tous les événements,
    quel que soit le profil qui les a produits. Chaque événement est
    horodaté et identifié par son profil (profile_id).
  Profil principal (main)
    Le premier profil connecté à la session est le profil principal. Ses
    questions (JSON AI Feed, Data AI Feed, AI_Query) constituent la
    timeline de référence de la session. Ce sont ces événements qui sont
    automatiquement rejoués sur les profils secondaires lors de leur
    connexion.
  Profils secondaires
    Tout profil connecté à la même session après le profil principal est
    secondaire. À la connexion, il reçoit en replay automatique toutes
    les questions du profil principal déjà posées, dans leur ordre
    d'origine. Ses propres réponses sont archivées dans la même session.
  Liberté de rejeu
    Chaque profil peut aussi avoir sa propre file de rejeu manuelle
    (questions supplémentaires ou croisements spécifiques). Seules les
    questions du profil principal sont automatiquement dupliquées sur les
    secondaires ; les questions posées directement sur un profil
    secondaire restent propres à ce profil.
  Threads dans l'historique
    Chaque connexion d'un profil crée un thread distinct dans l'arbre
    Threads / History. La ligne du thread affiche le profil, le statut
    de connexion, et le total des tokens in/out consommés par ce thread.
    Les événements rejoués d'un autre profil portent la mention
    replay_of_index indiquant l'événement d'origine.

ARCHIVAGE AUTOMATIQUE

Chaque fois que vous utilisez Connect, envoyez un JSON AI Feed, un Data
AI Feed, ou Send dans AI Analyst, l'échange est archivé automatiquement
dans la session commune :
  - le handshake Connect (avec le profil concerné)
  - le JSON d'analyse complet (JSON AI Feed)
  - l'échantillon de données brutes envoyé seul (Data AI Feed) — seule
    la recette d'échantillonnage est archivée, jamais les valeurs des
    lignes : les données ne sont jamais écrites sur disque ici
  - la question de suivi (Send)
  - la réponse IA reçue
  - un instantané query_core lorsque c'est pertinent
Vous n'avez rien à saisir manuellement.

BARRE D'OUTILS

In/out Session
    Import..., Import ZIP..., Export..., Open sessions folder.
    Utilisez ces options pour déplacer une session entre machines ou la
    partager. Une session est un dossier portable autonome. Comme les
    valeurs des lignes d'un Data AI Feed ne sont jamais archivées,
    exporter ou partager une session n'inclut jamais d'échantillon de
    données brutes.
Query Core
    Ouvre l'éditeur du JSON query_core de la session active, ou
    enregistre un nouvel instantané de l'état analytique courant.
Answer HTML
    Ouvre le visualiseur AI Answer sur la dernière réponse archivée de
    la session active.
Replay (n)
    Envoie les étapes de la file à AI Analyst comme plan de rejeu. (n)
    indique le nombre d'étapes en file. AI Analyst proposera un bouton
    Next pour les enchaîner une par une.
Clear queue
    Vide la file de rejeu et réinitialise la numérotation (colonne Sel).
⧉ Open Nav
    Onglet-bouton (fantôme) à droite du panneau de détail : ouvre le
    navigateur HTML (AI Answer / rapports) dans une fenêtre dédiée.
?   Ouvre cette page d'aide.
LISTE DES SESSIONS (gauche)
Liste toutes les sessions IA trouvées dans le workspace.
Double-cliquez sur une session pour aller à son onglet Manifest.
Clic droit sur une session : Rename..., Duplicate..., Queue session for
replay, Set active in Analyst, Delete.
QUERIES (milieu)
Affiche la query (ou les queries) liée(s) à la session sélectionnée,
avec le nom de la table. Une session se souvient de la query à partir de
laquelle elle a été créée, afin de pouvoir être rejouée sur la même
query ou sur une autre query/table compatible.
THREADS / HISTORY (droite, haut)
Un arbre de tous les événements archivés pour la session sélectionnée,
groupés par thread. Chaque thread correspond à une connexion d'un profil
et regroupe les questions et réponses qui ont suivi.
  Session setup (nœud racine)
    Regroupe les événements de configuration de la session (query_core,
    imports…) qui ne font partie d'aucun thread de chat IA.
  Ligne de thread
    Affiche : Thread N — profil (statut), avec en colonne Cost le total
    des tokens in/out consommés par ce thread dans la session.
    Exemple : Thread 4 — openrouter_claude_sonnet (connect ✓)  ↑1 234 ↓567
  Colonnes des événements :
    Sel    Numéro de sélection pour la file de rejeu.
    Type   Le type d'événement :
             Connect     handshake de protocole envoyé
             Disconnect  profil déconnecté
             AI_JSON     JSON d'analyse complet envoyé (JSON AI Feed)
             AI_Data     échantillon de données brutes envoyé seul
                         (recette + comptage uniquement, jamais les valeurs)
             AI_Query    question de suivi envoyée (Send)
             AI_Answer   réponse reçue de l'IA
    Cost   Tokens ↑in ↓out pour les événements AI_Answer (et leur requête
           associée par convention d'affichage).
    When   Horodatage de l'événement.
  Redimensionnement des colonnes
    Toutes les colonnes sont redimensionnables par glisser-déposer sur le
    séparateur d'en-tête. Clic droit sur un en-tête de colonne pour
    rétablir les largeurs par défaut.
  Hauteur de la zone History
    La séparation entre la liste des événements et la zone Detail
    (bas de panneau) est ajustable en faisant glisser la barre
    de séparation horizontale.
  Replay_of_index
    Les événements rejoués sur un profil secondaire (depuis le profil
    principal) affichent dans leur détail un champ replay_of_index
    indiquant l'index de l'événement d'origine dans la session.

SÉLECTIONNER DES ÉTAPES POUR LE REJEU

Cliquez sur la cellule Sel d'un événement Connect, AI_JSON, AI_Data ou
AI_Query pour l'ajouter à la file de rejeu. Un numéro apparaît indiquant
sa position dans la file. Re-cliquez pour le retirer.
La numérotation n'est pas réutilisée immédiatement : de petits sauts
sont normaux et sans conséquence. Changer de session conserve la
numérotation : vous pouvez piocher des étapes dans tout l'historique,
sur plusieurs sessions, avant de cliquer sur Replay.
Clic droit sur l'en-tête Sel : All on (select every AI_Query) sélectionne
tous les AI_Query de la session ; All off (deselect this session) vide la
sélection de cette session.
DETAIL (droite, bas)
Onglet Selected item
    Contenu brut du fichier de l'événement sélectionné (JSON envoyé ou
    réponse HTML reçue). Pour un événement AI_Data, c'est uniquement la
    recette et les comptages — les valeurs des lignes envoyées ne sont
    stockées nulle part.
Onglet Session info
    Contenu du manifest de la session (ai_session.json) : nom, profil
    principal, profils secondaires, query/table liée, date de création,
    index de tous les fichiers archivés, et totaux de tokens par profil.

REPLAY

Constituez une file (colonne Sel, éventuellement sur plusieurs sessions),
puis cliquez sur Replay. Les étapes sont envoyées à AI Analyst dans
l'ordre de leurs numéros de sélection. Dans AI Analyst, le bouton Next
prépare la prochaine étape de la file selon son type d'origine :
  Connect / AI_JSON  Reconstruit à neuf depuis ce qui est ouvert
                     maintenant, prêt à envoyer d'un clic de plus.
  AI_Data            La recette archivée est réappliquée aux données
                     actuellement ouvertes — jamais les anciennes
                     valeurs figées, puisqu'elles n'ont jamais été
                     conservées.
  AI_Query           Le texte de la question est renvoyé
                     automatiquement.
Cas particulier : replay automatique des profils secondaires
  Quand un profil secondaire se connecte à une session existante,
  les questions du profil principal déjà archivées sont rejouées
  automatiquement dans l'ordre, sans action manuelle dans AI Session
  Center. Cette file automatique reste indépendante de la file manuelle
  que vous pouvez construire ici pour des besoins spécifiques.

STRUCTURE DU DOSSIER SESSION

  <workspace>/AI/sessions/<nom_session>/
      ai_session.json                      manifest (tous profils)
      history/
          001_query_core.json
          002_ai_protocol_connect_sent.json  (profil principal)
          003_ai_answer.html
          004_ai_json_feed_sent.json
          005_ai_query_sent.json
          006_ai_answer.html
          018_ai_protocol_connect_sent.json  (profil secondaire)
          019_ai_answer.html
          020_ai_json_feed_sent.json         (replay auto depuis 004)
          021_ai_query_sent.json             (replay auto depuis 005)
Chaque fichier est numéroté séquentiellement dans la chronologie globale
de la session, tous profils confondus. La session est portable : elle peut
être copiée, archivée ou partagée sous forme de ZIP — sans jamais
transporter les valeurs des échantillons de données.
