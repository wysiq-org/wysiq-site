Export Table — ce qui se passe au clic sur EXEC (référence technique)

Page complémentaire de l'aide « copy_table » (bouton ? de la fenêtre Export
Table). Elle décrit l'ordre des opérations, pour qui veut comprendre les fichiers
écrits dans le workspace.
1) Avant EXEC (préparation)
• Target table, Owner et Target connection sont lus dans la fenêtre.
• Pour une connexion distante, le dialecte du profil (data_sources.json,
  engine_type) sert à construire le script CREATE TABLE affiché par le bouton
  SQL. Ce script est informatif : il n'est pas exécuté par le bouton SQL.
• Les modèles SQL de connection_type/<connecteur>/ (list_tables.sql…) servent
  à la découverte du catalogue ; ils ne sont pas exécutés par EXEC.
2) Au clic sur EXEC (ordre des opérations)
• Contrôle du nom ; si la table existe : « Overwrite it? » (Oui = remplacer).
• Lecture complète de la source : fichier relu en entier (masque Check file et
  shrink appliqués), table ou résultat SQL.
• DROP TABLE IF EXISTS puis CREATE TABLE dans la session DuckDB du workspace.
  WysiQ crée toujours une TABLE (les vues ne sont plus créées ici).
• Écriture du fichier .parquet et de la définition tables/<nom>.json
  (table_mode, source, colonnes, owner), mise à jour du registre
  tables/_registry.json et de la liste Main.
• Connexion distante choisie : écriture des lignes sur le serveur selon
  Remote push (Create / recreate, Append, Delete all rows then insert).
3) Après EXEC
• La table est disponible pour les Queries, le Table Catalog et le SQL
  Assistant.
• Depuis le SQL Assistant, une recette peut être enregistrée sous recipes/
  pour recréer la table plus tard ; elle est indépendante d'EXEC.
Voir aussi : copy_table (fenêtre Export Table), db_connections_json (fichiers
de connexion et dialectes).
