AI Observatory

Accès : Parameters ▸ AI ▸ Observatory (la fenêtre s'ouvre à la sélection de
l'onglet ; bouton Observatory Settings…) ; Main ▸ AI ▸ Observatory… ouvre la
page web de l'observatoire.
FENÊTRE « AI Observatory » — CONTRÔLES
  Enable activity tracking   active / désactive l'envoi des compteurs.
  Preset:                    Local test, WysiQ cloud, Enterprise intranet,
                             Custom (pré-remplit l'URL).
  Activity URL:              adresse du serveur d'activité.
  Mode:                      Anonymous counters (défaut : compteurs
                             uniquement) ou Enterprise opt-in (champs
                             supplémentaires, serveur d'entreprise).
  Fields sent                liste Field / Send / Privacy ; double-clic sur
                             une ligne optionnelle pour la passer ON / OFF.
  JSON preview               aperçu exact de ce qui sera envoyé.
  Privacy rule               rappel : aucune donnée, aucun SQL, aucun prompt,
                             aucun nom de table ; le thème est détecté
                             localement.
  Open AI observatory / Open Share observatory   ouvrent les pages web.
  Test local server          lance un serveur local de test (voir plus bas).
  Save / Close / ?           enregistrer, fermer, aide.
Cette page configure l'AI Observatory de WysiQ : ce que WysiQ compte,
ce qu'il n'envoie jamais, et comment alimenter soit l'observatoire public
wysiq.org, soit un serveur d'activité interne à l'entreprise.
Portée de cette version
Cette version du WysiQ Observatory suit l'usage IA (fournisseur, modèle,
tokens, langue, OS, version, identifiant d'instance anonyme) sur la page
AI observatory, et est structurellement prête à suivre les partages
réseau/sociaux et les exports (plateforme, type de contenu, format
d'export) sur la page séparée Share observatory — mais aucune
fonctionnalité WysiQ n'appelle encore le compteur de partage/export, donc
le Share observatory affichera zéro jusqu'à ce que cette instrumentation
soit ajoutée aux chemins de code de partage/export concernés dans une
version future.
Objectif
WysiQ peut comptabiliser l'utilisation réelle des IA sans transmettre les
données analysées. Le but est double :
1) www.wysiq.org / observatoire public WysiQ
   - afficher les IA les plus utilisées par les analyses WysiQ
   - compter les sessions IA, les modèles, les tokens et les versions WysiQ
   - rester en mode compteurs anonymes uniquement
2) Serveur entreprise / intranet
   - suivre la consommation IA interne de l'entreprise
   - consolider les tokens par modèle, fournisseur, version ou utilisateur
     si l'entreprise l'active
   - garder toutes les données sur un serveur choisi par le client, sans
     rien envoyer à wysiq.org
Mode public WysiQ
Le mode public doit rester minimal. Champs envoyés :
- version WysiQ
- langue WysiQ
- système d'exploitation
- identifiant d'instance anonyme
- fournisseur IA
- modèle IA
- nombre de requêtes
- tokens entrée / sortie / total
Ne jamais envoyer en mode public :
- données brutes
- noms de tables
- requêtes SQL
- prompts complets
- résultats d'analyse
- nom utilisateur Windows
- nom de poste
- email ou identité personnelle
- géolocalisation IP
Mode entreprise opt-in
Le mode Enterprise opt-in permet à une entreprise d'ajouter des champs
supplémentaires, mais uniquement sur SON propre serveur (jamais sur
wysiq.org) :
- User / login
- Query name
- Table name
- AI session id
- Workspace id
- Project / business unit
Ces champs sont des options explicites, à activer une par une dans la liste
« Fields sent » de la fenêtre de configuration. Ils servent à une DSI ou une
équipe data qui veut suivre la consommation IA interne par utilisateur ou
par projet.
Fichiers de paramétrage WysiQ
La configuration locale est stockée dans le workspace :
   <workspace>/activity/activity_config.json
Ce fichier contient notamment :
- enabled : active/désactive le suivi
- server_url : URL du serveur d'activité cible
- instance_id : identifiant anonyme créé une seule fois par poste
- tracking_mode : anonymous ou enterprise
- fields : champs activés dans la liste de la fenêtre de configuration
- send_errors_to_log : conserve les erreurs locales d'envoi
Les journaux locaux du poste WysiQ sont :
   <workspace>/activity/activity_sent.jsonl
   <workspace>/activity/activity_errors.jsonl
activity_sent.jsonl permet de vérifier exactement ce que WysiQ a tenté
d'envoyer (utile pour contrôler qu'aucune donnée sensible ne part).
activity_errors.jsonl permet de diagnostiquer une URL serveur invalide ou
un serveur arrêté.
Serveur local de test (sur ce poste)
Le bouton « Test local server » lance, dans une fenêtre CMD visible, le
serveur de test local fourni avec WysiQ :
   py -m xiquery.activity.local_activity_server
Pages locales :
   http://127.0.0.1:8088/ai.html         AI observatory (compteurs d'usage IA)
   http://127.0.0.1:8088/share.html      Share observatory (compteurs partages + exports)
   http://127.0.0.1:8088/ping            test de disponibilité du serveur
Endpoint de réception des événements :
   http://127.0.0.1:8088/api/activity
Fichier de stockage du serveur local :
   <workspace>/activity/server_data/activity_events.jsonl
Ce serveur local est uniquement destiné aux tests sur le poste de
développement : il s'arrête quand on ferme sa fenêtre CMD et ne doit pas
être utilisé pour un suivi réel en production.
Serveur entreprise / intranet : activation détaillée
WysiQ fournit un serveur autonome clé en main pour une entreprise qui veut
alimenter ses PROPRES compteurs d'activité IA WysiQ, sans rien envoyer à
wysiq.org. C'est un fichier Python unique, sans dépendance au reste de
WysiQ : il ne nécessite que Python 3 standard (aucune librairie à
installer), ce qui permet de le copier et de le lancer sur n'importe quel
poste ou serveur du réseau de l'entreprise.
Ce fichier est déjà fourni et copié automatiquement dans chaque workspace,
sans action de votre part, sous :
   <workspace>/techroom/WYSIQ_ACTIVITY_SERVER.py
   <workspace>/techroom/WYSIQ_ACTIVITY_SERVER.bat
   <workspace>/techroom/WYSIQ_ACTIVITY_SERVER_README_FR_EN.txt
Étapes pour l'activer et alimenter les compteurs de l'entreprise :
1) Récupérer les fichiers dans le workspace :
      <workspace>/techroom/WYSIQ_ACTIVITY_SERVER.py
      <workspace>/techroom/WYSIQ_ACTIVITY_SERVER.bat
2) Les copier ensemble sur la machine qui jouera le rôle de serveur
   d'activité (un serveur intranet, ou simplement un poste toujours
   allumé et accessible par les autres postes WysiQ pour un premier
   essai).
3) Lancer le serveur sur cette machine. Sous Windows, le plus simple
   est de double-cliquer sur WYSIQ_ACTIVITY_SERVER.bat : il détecte
   automatiquement Python (py ou python), affiche un message clair s'il
   n'est pas installé, et laisse la fenêtre ouverte pour suivre les
   journaux d'activité. Sinon, en ligne de commande (Windows, Linux,
   macOS) :
      py WYSIQ_ACTIVITY_SERVER.py
   ou :
      python WYSIQ_ACTIVITY_SERVER.py
   Note : le fichier .bat n'est copié automatiquement que dans les
   nouveaux workspaces (ou les techroom existants qui ne l'ont pas
   encore) ; un workspace déjà créé avant cette version ne le recevra
   pas tout seul, il faut alors le recopier manuellement depuis
   <workspace>/techroom/ ou depuis le dossier assets/techroom/ du
   programme.
   Variables d'environnement optionnelles, à définir avant le lancement
   si les valeurs par défaut ne conviennent pas :
      WYSIQ_ACTIVITY_HOST   défaut 0.0.0.0 (écoute sur toutes les interfaces)
      WYSIQ_ACTIVITY_PORT   défaut 8088
      WYSIQ_ACTIVITY_DATA   défaut ./server_data (dossier de stockage JSONL)
4) Vérifier depuis un navigateur, sur cette machine ou sur un autre poste
   du réseau :
      http://NOM_DU_SERVEUR:8088/ping
      http://NOM_DU_SERVEUR:8088/ai.html         AI observatory (compteurs IA)
      http://NOM_DU_SERVEUR:8088/share.html      Share observatory (compteurs partages + exports)
5) Sur CHAQUE poste WysiQ qui doit alimenter ce serveur entreprise,
   ouvrir :
      Settings ▸ Parameters… ▸ AI ▸ Observatory ▸ « Observatory Settings… »
6) Choisir le preset :
      Enterprise intranet
7) Renseigner l'URL d'activité avec le nom ou l'IP du serveur de
   l'entreprise :
      http://NOM_DU_SERVEUR:8088/api/activity
À partir de cet instant, chaque session IA terminée sur ce poste WysiQ
envoie ses compteurs (fournisseur, modèle, tokens, langue, OS, version)
vers ce serveur d'entreprise. Les pages /ai.html et /share.html se
rafraîchissent automatiquement toutes les 5 secondes : il suffit de les
laisser ouvertes pour suivre l'activité en direct.
Stockage côté serveur entreprise :
   server_data/activity_events.jsonl
Chaque ligne est un événement JSON indépendant. Ce format est simple à
relire avec Python, Excel/PowerQuery, DuckDB, SQLite, PostgreSQL ou un
outil BI, pour une exploitation plus poussée que les deux pages HTML
fournies.
Les deux points d'API consultables (utilisés par les pages HTML, mais
aussi directement exploitables par un outil BI) renvoient le même type de
réponse JSON :
   GET /api/stats/public   compteurs agrégés, sans détails d'événements
   GET /api/stats/admin    mêmes compteurs, plus la liste des 50 derniers
                           événements bruts (recent_events)
Réponse type :
   {
     "totals": {
       "active_instances": 12, "ai_sessions": 340,
       "total_tokens": 512000, "input_tokens": 410000,
       "output_tokens": 102000, "events_count": 480
     },
     "top_providers": [["anthropic", 300000], ["openai", 212000]],
     "top_models":    [["claude-sonnet-4-6", 280000], ["gpt-4o", 232000]],
     "languages":      [["fr", 300], ["en", 40]],
     "os":             [["Windows", 320], ["Linux", 20]],
     "versions":       [["1.2.4", 340]]
   }
Le serveur entreprise réutilise exactement les mêmes fichiers HTML et le
même calcul de compteurs que le serveur local de test : les deux
implémentations sont maintenues identiques afin qu'un même tableau de
bord se comporte de la même façon, que les données viennent d'un test
local ou d'un vrai serveur d'entreprise.
Règle de confidentialité
Le serveur WysiQ public sait qu'une analyse IA a eu lieu, mais ne sait
jamais de quoi elle parlait.
Les champs User, Query, Table, Project et Workspace sont réservés aux
serveurs d'entreprise et doivent rester un choix explicite du client,
jamais activés par défaut, et jamais envoyés vers www.wysiq.org.
Détection du thème d'activité
WysiQ peut ajouter un thème d'activité compact aux compteurs d'usage IA, par
exemple energy, finance_accounting ou manufacturing. Le thème est calculé en
local à partir d'une liste plate de noms de tables et de colonnes avec :
  WysiQ/activity/domain_keywords.json       dictionnaire entreprise optionnel
  activity/domain_keywords.json             dictionnaire standard livré
                                            (dossier du programme)
Aucune ligne de données, aucune requête SQL, aucun prompt, aucun DDL, aucune clé,
aucune relation, aucun index et aucune liste brute de colonnes ne sont transmis à
l'Observatory WysiQ. Seuls le thème calculé, son libellé et son niveau de
confiance sont envoyés avec les compteurs de tokens.
Lorsqu'une query est sauvegardée, WysiQ stocke aussi le thème détecté dans le
JSON de la query. Lorsqu'une fenêtre AI Analyst est ouverte depuis une query ou
un graphe, le thème est recalculé depuis le contexte courant afin que la page AI
Activity puisse afficher les usages IA par domaine métier pratique.
