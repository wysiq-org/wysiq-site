Notebooks de tests — Aide

Les notebooks sont des tests statistiques autonomes, écrits en Python
pur dans le dossier stats/notebooks/ du programme. Chaque fichier est lisible et
auditable : formule, dépendances, conditions minimales et notes de
résultat sont directement dans le code — aucune boîte noire.
Accès : bouton Params de la fenêtre Statistical Tests, ou Settings ▸
Parameters… ▸ onglet Statistics.
L'onglet Statistics propose : cadre « Statistics execution parameters »
(p-adjust par défaut : BH, Holm, Bonf, none), la liste des notebooks, le
cadre « Per-test parameters » (paramètres du notebook sélectionné, listes
déroulantes) et le bouton ? (cette aide).

1) CONCEPT

  Un notebook est un module Python avec deux éléments :
    META  dict décrivant le test (clé, titre, description).
    run(context)  fonction recevant les données et
                  renvoyant {test, stat, p, effect, note}.
  Les notebooks sont intégrés dans le moteur de tests :
  ils apparaissent dans la grille de résultats exactement
  comme les tests natifs, avec les mêmes colonnes.
  context reçu par run() :
    "A"      liste de valeurs (série A sélectionnée)
    "B"      liste de valeurs (série B sélectionnée)
    "params" dict des paramètres configurés dans Params

2) NOTEBOOKS DISPONIBLES

── Pearson
  Corrélation linéaire entre deux séries alignées.
  Fichier : notebooks/pearson.py
  Entrée  : A et B (au moins 3 points communs finis).
  Sortie  : r (stat), p-value (SciPy ou vide), r (effect).
  Dépend  : NumPy. SciPy pour la p-value.
── ADF (Augmented Dickey-Fuller)
  Test de stationnarité / racine unitaire sur la série A.
  Fichier : notebooks/adf.py
  Entrée  : A (au moins 8 points finis).
  Sortie  : stat t, p-value, note "lag=X method=...".
  Dépend  : statsmodels (méthode principale).
            Fallback NumPy si statsmodels absent
            (régression manuelle sur les différences).
  Params  : Autolag (AIC/BIC/t-stat/none),
            Regression (c/ct/ctt/n),
            Max lag.
  Interpréter : p faible → rejet de la racine unitaire
                → série probablement stationnaire.
── Granger causality
  Test si les valeurs passées de B améliorent la
  prédiction de A (causalité au sens de Granger).
  Fichier : notebooks/granger.py
  Entrée  : A et B (au moins 12 points communs finis).
  Sortie  : F-stat, p-value, note "best lag=X method=...".
  Dépend  : statsmodels (requis — pas de fallback complet).
  Params  : Max lag (défaut 5, max 8).
  Important : "Granger causality" est une causalité
              prédictive, pas causale au sens strict.
              Résultat sensible au lag choisi.
── Change point
  Détecte un changement de moyenne dans la série A par
  scan de toutes les coupures possibles.
  Fichier : notebooks/change_point.py
  Entrée  : A (au moins 18 points finis).
  Sortie  : t-stat à la meilleure coupure, Cohen d
            (effect), note "idx=X mean_before=... after=...".
  Dépend  : NumPy uniquement.
  Params  : Min size (taille minimale de chaque segment,
            défaut 8).
  Pas de p-value calculée.
── Mutual information
  Mesure de dépendance non linéaire entre A et B.
  Fichier : notebooks/mutual_info.py
  Entrée  : A et B (au moins 8 points communs finis).
  Sortie  : MI brute (stat), MI normalisée (effect),
            note "normalized=X method=...".
  Dépend  : scikit-learn pour la méthode principale.
            Fallback histogram 2D si sklearn absent.
  Params  : Bins (défaut auto = sqrt(n), max 24).
  0 = indépendance totale. Pas de p-value.
3) PARAMÈTRES FINS (Params)
  L'onglet Statistics de Parameters (bouton Params de
  Statistical Tests) permet de configurer les paramètres de chaque test :
  ADF       Autolag, Regression, Max lag
  KPSS      Regression, N lags
  Granger   Max lag
  Change pt Min size
  Mutual info  Bins
  ACF       Max lag
  Rolling corr  Rolling window
  Chi2      Bins
  Shapiro   Warn above N (seuil d'avertissement)
  Mann-Kendall  Alpha
  Ces paramètres sont persistés dans le workspace et
  s'appliquent à tous les runs suivants.

4) TRANSPARENCE ET AUDIT

  Chaque fichier notebook est autonome et court
  (< 60 lignes en général). Il est conçu pour être lu
  et vérifié sans outillage particulier.
  Pour auditer un test :
  1. Ouvrir stats/notebooks/<nom>.py (dossier du programme)
  2. Lire la fonction run(context) ligne par ligne
  3. Vérifier META pour les métadonnées du test
  4. Comparer avec la documentation de référence
     (SciPy, statsmodels, sklearn selon le cas)
  En cas d'absence de dépendance (statsmodels, sklearn) :
  - Granger et ADF (statsmodels) : résultat absent ou
    fallback NumPy avec note "method=fallback".
  - Mutual info (sklearn) : fallback histogram 2D
    avec note "method=hist2d".
  - Dans tous les cas, la note indique la méthode
    effectivement utilisée.

5) DÉPENDANCES REQUISES

  NumPy      Requis pour tous les notebooks.
  SciPy      p-values Pearson, certains fallbacks.
  statsmodels  ADF (méthode principale), Granger (requis).
  scikit-learn  Mutual info (méthode principale).
  Sans statsmodels : Granger ne produit pas de résultat.
  Sans scikit-learn : Mutual info passe en fallback hist2d.
