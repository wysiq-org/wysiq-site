Connexions DB — fichiers JSON des profils (WysiQ)

Accès : bouton ? à côté de Catalog dans la fenêtre Sources de données
(Main ▸ Database ▸ DB Connection).
Cette page décrit les fichiers que la fenêtre Sources de données lit et écrit,
pour qui veut les lire ou les corriger directement avec un éditeur de texte
(WysiQ fermé ou après un ⟳ Reload). Il n'y a plus d'onglet « DB connection »
dans Parameters : toute la saisie courante se fait dans Sources de données.
Voir aussi : help/fr/datasource.txt (la fenêtre Sources de données)
             help/fr/db_connections_json.txt (référence complète des fichiers)
Ce que vous pouvez modifier ici
data_sources.json
  Un objet par profil de connexion. Chaque profil porte l'identité de son
  connecteur — family, provider, connector_service, connector_label,
  engine_type — et les paramètres non sensibles (host, port, database, schema,
  username, mode SSL, ...).
  Les mots de passe ne sont jamais à saisir dans ce fichier. Selon la case PWD de
  la fenêtre Sources de données, un profil peut contenir password_enc (forme
  brouillée) ; cette valeur est produite par Sources de données, pas à la main.
db_connection.json
  Optionnel. Définit les types de connecteurs et les champs du formulaire.
  Présent uniquement si votre workspace surcharge le catalogue fourni.
Préfixes SQL optionnels
  sql_before_select et sql_before_create, utilisés par les flux DuckDB et par
  les scripts de création générés pour le profil. Ils sont décrits dans
  db_connections_json.txt.
Les cinq champs d'identité
Tout profil enregistré conserve ces clés explicitement. Ne les supprimez pas :
c'est ainsi que WysiQ retrouve le bon connecteur et le bon moteur au
rechargement.
  family              Local, Server, Cloud, API / NoSQL
  provider            Generic, Microsoft, Azure, AWS, Google Cloud, ...
  connector_service   identifiant interne du connecteur, ex. aws_redshift
  connector_label     le libellé affiché, ex. « Amazon Redshift »
  engine_type         le moteur technique, ex. postgresql
provider et engine_type répondent à deux questions différentes : qui exploite le
service, et quel moteur il parle. Plusieurs fournisseurs partagent un même
moteur — c'est normal et voulu.
Modification manuelle
Modifiez les fichiers avec un éditeur de texte, puis ⟳ Reload dans Sources de
données. Un fichier mal formé est signalé plutôt qu'ignoré silencieusement ;
en revanche, un fichier syntaxiquement valide mais au engine_type erroné
échouera simplement à la connexion. Ne modifiez ce champ que si vous savez
pourquoi.
Les clés commençant par un tiret bas sont de la documentation et sont ignorées
par WysiQ.
Ce qui n'est jamais enregistré
access_token, refresh_token, client_secret, private_key, secret_access_key et
service_account_private_key n'atteignent aucun fichier, quoi que vous saisissiez
dans le formulaire. Lorsqu'un gestionnaire de secrets ou un identifiant externe
existe, WysiQ enregistre la référence, jamais la valeur du secret.
Les mots de passe suivent la case PWD de Sources de données : décochée par
défaut (session uniquement), ou écrits sous la clé password_enc sous forme
brouillée. Ce brouillage empêche la lecture accidentelle ; ce n'est pas un
chiffrement fort. Voir help/fr/datasource.txt.
