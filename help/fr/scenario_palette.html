PALETTE SCÉNARIO — Courbes cibles manuelles

Accès : bouton Scenario de la fenêtre graphique ou rond Sc de la Graph Remote.
Rôle
Un Scénario est une courbe cible éditée manuellement et affichée au-dessus du graphique courant. Il sert à tester rapidement des hypothèses : dessiner une cible, l'alimenter depuis une série existante, changer le type d'interpolation, puis éventuellement la convertir en série WysiQ normale avec → Series ou l'envoyer à l'IA avec → AI. La table source et la requête SQL ne sont pas modifiées.
Flux conseillé
1. Saisir un nom de scénario puis utiliser New.
2. Activer DRAW et cliquer/glisser sur le graphique pour ajouter des points de contrôle.
3. Utiliser MOVE pour déplacer les points existants.
4. Choisir le type de Curve et son paramètre.
5. Utiliser COMPUTE pour recalculer la courbe sans refaire un Feed depuis la référence.
6. Utiliser → Series quand le scénario doit devenir une série normale utilisable par les métriques, les Areas, l'AI feed et les exports.
7. Utiliser → AI pour déposer le JSON du scénario actif dans l'AI Feed Stack (sans le convertir en série).
Contrôles du haut
Nom du scénario : nom du scénario actif.
New/Rename/Duplicate/Delete : gestion des scénarios (liste déroulante
d'action ; aussi au clic droit ou Ctrl+clic sur la liste des scénarios).
Style : choix de la couleur (pastilles ou More...), de la taille et de
l'affichage des points de contrôle (case « Show points ») ; Close ferme. La taille grossit le trait ET les points de contrôle. Quand une vraie série est créée ensuite, elle peut hériter du style du scénario, mais la série reste modifiable dans la palette Series.
Import : ouvre le catalogue de scénarios.
JSON : fenêtre JSON du scénario — Copy, Paste, Apply (applique le JSON édité), Export, Import, Close.
Save : sauvegarde les scénarios dans la Query.
Vars : ouvre la fenêtre Variables de la query active — poussez les refs à l'extrême
pendant que DRAW/MOVE reste actif ; laissez le picker ouvert (Stay open) pour comparer
l'hypothèse sur tout le graphe.
Liste des scénarios et SUM
La liste sélectionne le scénario actif. Seul le scénario actif reçoit les éditions DRAW/MOVE.
SUM affiche le total vivant des Y du scénario interpolé sur les X du graphique courant. Le total applique le même Unit factor que les SUM de la palette Table. Si les X du graphique ne sont pas disponibles, WysiQ utilise en secours la somme des points de contrôle.
Sample from et Feed
Sample from choisit une série tracée, de base ou virtuelle, utilisée par Feed et par SNAP_TO_TREND.
Feed échantillonne la série de référence et remplace les points du scénario par ces points échantillonnés. Si aucune série n'est choisie, une boîte « Select reference series » la demande (OK / Cancel). La boîte « Calc — <série> » règle ensuite l'échantillonnage : Auto ≤ N pts, First N, Last N ou Every N pt (avec une limite Max facultative) ; l'estimation du nombre de points s'affiche ; Apply valide, Cancel abandonne. C'est pratique pour partir d'une série réelle, puis modifier manuellement l'hypothèse.
Changer de Curve après un Feed est normal : les mêmes points échantillonnés peuvent être interprétés en STEP, BEZIER, LEGENDRE, etc.
Toggles
DISPLAY : affiche/masque les overlays de scénarios.
DRAW : ajoute/édite des points par dessin sur le graphique.
MOVE : déplace les points existants du scénario.
Snap X : cale les positions X des points sur le X du graphique le plus proche. Y reste la valeur cliquée/glissée.
Monotone : force les points/la courbe à rester globalement croissants ou décroissants, pour limiter les oscillations non voulues.
Types de Curve et paramètre
Liste Curve : LINEAR, STEP, PCHIP, SPLINE, BEZIER, EASE_INOUT, SCURVE, EXPONENTIAL, SNAP_TO_TREND, LEGENDRE.
Le slider change de nom selon la Curve sélectionnée (le champ à côté accepte une saisie, Entrée pour valider). Pour la plupart des courbes c'est un paramètre continu (0..1) ; pour LEGENDRE c'est Degree (1..12).
LINEAR — paramètre : Smoothing
Interpolation linéaire entre les points de contrôle. Smoothing > 0 applique un lissage mobile sur la courbe calculée. Utile pour les cibles simples et les esquisses rapides.
PCHIP — paramètre : Shape
Interpolation cubique par morceaux qui préserve la forme : elle respecte les intervalles monotones et évite les dépassements artificiels près des pics ou des creux. Pas d'extrapolation. Utile pour des cibles réalistes sans oscillations.
SPLINE — paramètre : Natural
Spline cubique naturelle (continuité C2) passant par tous les points ; le modèle complet (coefficients) est enregistré dans le JSON. Pas d'extrapolation hors du premier / dernier point.
BEZIER — paramètre : Tension
Spline lisse passant par tous les points de contrôle. Tension 0 donne un rendu presque linéaire entre les points ; Tension 1 donne une courbe plus ronde. La courbe passe toujours par les points. Utile pour les cibles continues naturelles.
STEP — paramètre désactivé
Interpolation en paliers. La valeur reste constante jusqu'au point suivant. Utile pour seuils, capacités, tarifs, dates réglementaires ou changements on/off. Le slider est désactivé car STEP n'a pas de paramètre continu.
EASE_INOUT — paramètre : Tension
Départ et arrivée adoucis entre les points, avec une vitesse réduite près des bornes du segment. Utile pour des transitions progressives, ramp-up/ramp-down et cibles sans rupture brutale.
SCURVE — paramètre : Steepness
Transition logistique en S entre les points. Steepness faible se rapproche du linéaire ; Steepness fort concentre le changement au milieu du segment. Utile pour les scénarios d'adoption/diffusion.
EXPONENTIAL — paramètre : Exponent
Transition de forme exponentielle entre les points. Exponent faible est proche du linéaire ; Exponent fort produit une accélération ou décélération plus marquée en fin de segment. Utile pour les hypothèses de croissance ou de décroissance.
SNAP_TO_TREND — paramètre : Trend
Commence en suivant la pente locale de la série Sample from près du premier point de contrôle, puis rejoint progressivement le scénario dessiné. Trend 0 donne peu d'influence à la tendance réelle ; Trend 1 conserve cette influence plus longtemps. Nécessite une série Sample from.
LEGENDRE — paramètre : Degree
Ajuste un modèle polynomial de Legendre par moindres carrés sur les points de contrôle, sur la plage X du premier au dernier point. Degree (1..12) fixe l'ordre du polynôme : valeurs basses = tendance lisse globale, valeurs hautes = plus de détail mais risque d'oscillations si peu de points. Hors de la plage X des points de contrôle : NaN (pas d'extrapolation). Utile pour des courbes d'hypothèse polynomiales lisses avec peu de poignées.
Actions
Undo : annule la dernière opération scénario une étape à la fois : point ajouté, point supprimé, point déplacé, déplacement global, Clear ou Feed.
Redo : réapplique l'opération qui vient d'être annulée. Toute nouvelle édition vide la pile Redo.
Clear : supprime les points du scénario courant.
COMPUTE : applique les paramètres courants et recalcule la courbe à partir des points actuels. Il ne rééchantillonne pas la référence.
→ Series : transforme le scénario en série WysiQ normale. Ensuite la série peut être utilisée dans les métriques, Areas, AI sessions, tables et exports comme toute autre série.
→ AI : dépose le JSON du scénario actif (même contenu que JSON / catalogue) dans l'AI Feed Stack. Ne crée pas de série — utiliser → Series pour cela.
Conseils
Utiliser Feed pour partir du réel, puis DRAW/MOVE pour construire l'hypothèse cible.
Utiliser BEZIER ou EASE_INOUT pour les cibles continues visuelles.
Utiliser LEGENDRE pour des tendances polynomiales lisses avec peu de points.
Utiliser STEP pour les seuils administratifs ou de capacité.
Utiliser SCURVE pour les scénarios d'adoption.
Utiliser EXPONENTIAL pour les scénarios d'accélération/décroissance.
Utiliser SNAP_TO_TREND quand le scénario doit démarrer de façon cohérente avec la tendance réelle actuelle.
Performance DRAW/MOVE
Pendant le dessin et le déplacement, WysiQ reste sur le chemin rapide overlay/blit : le graphique complet n'est pas recalculé à chaque mouvement de souris. Le plot complet est conservé pour les scénarios déjà convertis en vraie série, car il faut alors resynchroniser la table de travail.
