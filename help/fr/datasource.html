Sources de données — profils de connexion (WysiQ)

Accès : Main ▸ Database ▸ DB Connection (exige un workspace ouvert).
Processus type :
  + New → Family / Provider / Type → remplir les champs → Test → Save
  → Connect → Catalog (choisir les tables) → les tables apparaissent dans Main.
Cette fenêtre conserve les profils de connexion que WysiQ utilise pour atteindre
vos données : fichiers locaux, bases serveur, bases cloud managées, entrepôts
cloud, stockage objet, API et bases NoSQL. Un profil est réutilisé ensuite par
l'Assistant SQL, le Catalogue de tables et les imports/exports.
Les paramètres non sensibles sont enregistrés dans data_sources.json, dans votre
workspace. Les mots de passe et les jetons restent en mémoire de session par
défaut — voir « Enregistrement des mots de passe » plus bas.
Voir aussi : help/fr/db_connections_json.txt (fichiers, modèles SQL, dialectes)
             help/fr/params_db_connection.txt (fichiers JSON des profils)
Choisir un connecteur : Family, Provider, Type
La liste des connecteurs est filtrée par deux listes déroulantes (Family:,
Provider:), puis une liste :
Famille      La nature de la source : Local, Server, Cloud, API / NoSQL.
Fournisseur  Qui l'exploite : Generic, Microsoft, Azure, AWS, Google Cloud,
             Oracle Cloud, Snowflake, Databricks, MongoDB, etc.
Type         Le service réel, par exemple « Azure SQL Database »,
             « Amazon Redshift », « Google BigQuery », « IBM Db2 ».
Choisissez la famille, puis le fournisseur, puis le type dans la liste. La
valeur « All » dans l'une des listes élargit le choix. Exemples :
  Famille Cloud   > Fournisseur AWS     > Type Amazon Redshift
  Famille Cloud   > Fournisseur Azure   > Type Azure SQL Database
  Famille Server  > Fournisseur Generic > Type IBM Db2
  Famille Local   > Fournisseur WysiQ   > Type DuckDB
Les champs du formulaire changent avec le type. Seuls les champs utiles au
connecteur sont affichés ; les exemples indiquent le format attendu.
Cloner un connecteur
Cliquez avec le bouton droit sur un connecteur de la liste Type ▸ « Clone this
connector… » pour le cloner.
WysiQ demande une clé (le nom du dossier) et un libellé, puis copie le
connecteur dans votre workspace sous connection_type/<clé>/.
La copie déclare le même moteur que l'original : elle fonctionne immédiatement
— même pilote, même dialecte SQL, mêmes requêtes de catalogue. Aucun code n'est
nécessaire.
Utilisez-la lorsqu'un service demande une variante propre à votre site : un nom
de pilote ODBC imposé, un champ supplémentaire, un port par défaut différent,
ou un list_tables.sql ajusté. Modifiez db-connection.json ou les fichiers SQL
dans le nouveau dossier ; le connecteur d'origine n'est jamais modifié, et
votre copie survit aux mises à jour de WysiQ.
La clé doit commencer par une lettre et ne contenir que des lettres, des
chiffres et des tirets bas. Un nom déjà utilisé est refusé.
Fournisseur et moteur sont deux choses différentes
Beaucoup de services cloud réutilisent un moteur standard. Amazon RDS
PostgreSQL, Azure Database for PostgreSQL et Google Cloud SQL PostgreSQL sont
trois services distincts, mais tous trois parlent PostgreSQL. WysiQ enregistre
les deux informations :
  provider      l'environnement (AWS, Azure, Google Cloud, ...)
  engine_type   le moteur technique (postgresql, mysql, sqlserver, oracle, ...)
C'est pourquoi un nouveau service managé peut être proposé sans nouveau pilote :
il déclare simplement un moteur existant. Cela garantit aussi qu'un même moteur
se comporte partout de la même façon — même dialecte SQL, mêmes requêtes de
catalogue.
Liste « Sources » (panneau de gauche)
Chaque ligne est un profil nommé, par exemple « Prod Oracle » ou « Analytics
Snowflake ». Colonnes :
  C        ● = profil connecté pour la session.
  Source   icône de la famille + nom du profil.
  DB       numéro du profil (le même que la colonne DB de la fenêtre Main).
  ⟳ Reload  Recharge depuis le disque le catalogue des types de connecteurs
            (utile après avoir cloné ou modifié un connecteur).
  + New     Crée un profil avec le connecteur par défaut. Renommez-le dans le
            champ Name ; le nom doit être unique.
  Delete    Supprime le profil sélectionné après confirmation. Les secrets de
            session de ce profil sont effacés en même temps.
Clic droit (ou Ctrl+clic) sur un profil :
  Duplicate…  copie le profil sous un nouveau nom (« nom (2) » proposé) ;
  Rename…     renomme le profil ;
  Delete…     supprime le profil après confirmation.
Boutons
Test      Ouvre une connexion courte et exécute une sonde inoffensive
          (typiquement SELECT 1, une requête de version, ou un ping). Rien
          n'est écrit dans votre base. Une fenêtre de trace affiche chaque
          étape : import du pilote, connexion, version, nombre de tables,
          fermeture. Copy copie la trace ; Close la ferme.
Save      Écrit le profil dans data_sources.json, dans le workspace. Les mots
          de passe suivent la case PWD décrite plus bas.
Connect   Marque le profil actif pour cette session afin que les autres
          fenêtres puissent l'utiliser. Aucun fichier JSON n'est réécrit. Le
          bouton affiche ensuite Disconnect.
Catalog   Ouvre le Catalogue de tables pour ce profil : schémas, tables, vues
          et colonnes lus sur le serveur. Disponible uniquement pour les
          connecteurs qui gèrent réellement le catalogue.
?         (à côté de Catalog) Ouvre l'aide « params_db_connection » sur les
          fichiers JSON des connexions.
?         (en haut à droite) Ouvre cette aide.
Enregistrement des mots de passe
Par défaut, les mots de passe et les jetons vivent en mémoire pour la session
en cours et ne sont jamais écrits sur disque. Après un redémarrage de WysiQ,
vous les saisissez à nouveau.
La case PWD à côté de Save change ce comportement :
  décochée   « Passwords are session-only — never saved to disk. »
             Rien de sensible n'atteint data_sources.json.
  cochée     Le mot de passe est écrit dans le profil sous la clé
             password_enc, sous une forme brouillée (jamais en clair).
À lire attentivement : ce brouillage sert à empêcher la lecture accidentelle du
fichier JSON — un collègue qui l'ouvre, une capture d'écran, une sauvegarde
oubliée. Ce n'est pas un chiffrement fort. Quiconque possède le fichier et
l'application peut retrouver le mot de passe. Utilisez la case pour le confort
sur une machine personnelle ; laissez-la décochée pour des identifiants de
production, ou sur toute machine ou dossier que vous ne maîtrisez pas.
Quel que soit le réglage, ces valeurs ne sont jamais écrites sur disque :
access_token, refresh_token, client_secret, private_key, secret_access_key,
service_account_private_key.
Lorsqu'un pilote est absent
WysiQ ne charge aucun pilote de base au démarrage : un paquet optionnel manquant
ne peut donc pas empêcher l'application de se lancer. Le pilote est importé à la
première connexion. S'il est absent, le Test indique exactement quoi installer,
pour l'interpréteur Python qui exécute WysiQ, par exemple :
  The postgresql connector requires the 'psycopg2-binary' package.
  Install it with: pip install psycopg2-binary
Certains connecteurs sont listés pour permettre de préparer le profil alors que
leur moteur n'est pas encore câblé dans cette version. Le Test le dit clairement
plutôt que de simuler un succès.
Fichiers du workspace
data_sources.json
  Un objet par profil : l'identité du connecteur (family, provider,
  connector_service, connector_label, engine_type) et les paramètres non
  sensibles.
connection_type/<connecteur>/
  Un dossier par connecteur, copié depuis l'application à la création du
  workspace. Il contient la définition des champs et, pour les connecteurs SQL,
  des modèles SQL modifiables comme list_tables.sql. Votre copie prime sur la
  version fournie, ce qui permet à un DBA d'ajuster une requête après revue.
connexions_cache/
  Caches des listes d'objets (tables, entity sets, collections) produits quand
  vous générez un catalogue. Découverte en lecture seule ; rien n'est exécuté
  sur le serveur.
Réglages de sécurité par défaut
WysiQ est orienté lecture. Les connecteurs cloud activent TLS/SSL par défaut et
conservent la validation des certificats ; aucun mode non sécurisé n'est choisi
à votre place. Le Test n'exécute jamais d'instruction destructrice.
Conseils
  • Vérifiez le pare-feu, le VPN et le DNS avant de suspecter le connecteur.
  • Sous Windows, « localhost » se résout d'abord en IPv6 ; WysiQ force
    127.0.0.1 pour PostgreSQL car pg_hba.conf n'autorise en général que
    l'adresse IPv4.
  • Pour les connecteurs ODBC (Ingres, Db2, Sybase ASE, ...), le nom du pilote
    doit correspondre exactement à l'entrée de l'administrateur de sources de
    données ODBC de Windows.
  • Pour Oracle Cloud en mTLS, renseignez le répertoire du wallet.
  • Le service Oracle et connector_service sont deux champs distincts : le
    premier est le nom de service Oracle, le second l'identifiant interne du
    connecteur WysiQ.
Langue de l'aide : liste Language en bas de chaque fenêtre d'aide, ou Settings ▸ Manual… (Help Folder).
